# GIGORAVE V188.120 — аудит ZIP не превращается в Word

Это **патч поверх существующей рабочей установки**, а не самостоятельный проект. Перед обновлением останови бота и сделай резервную копию рабочей папки. Скопируй содержимое ZIP поверх проекта, не удаляя `.env`, `data`, SQLite-базы, старые задания, `src/index.js` и файлы, отсутствующие в патче.

Причина ошибочного Word в V188.119: `parseDocumentArtifactRequest()` видел одновременно «Верни», «отчётом» и «файл» в команде Astra и автоматически назначал DOCX, хотя пользователь просил **ZIP**. Это подтверждено воспроизведением классификатора из V188.119 на реальном типе команды. Дополнительно незавершённый Word-режим меню мог переоформить следующее сообщение с вложением в запрос на DOCX.

Исправления V188.120: текст Astra-аудита ZIP имеет приоритет над генерацией документов; неявный Word по словам «отчёт»+«файл» удалён; входящий Telegram-документ обходит устаревший режим Word; для Astra-аудита с прикреплённым `.txt`/`.docx` вместо `.zip` бот сообщает, что требуется настоящий ZIP, и не запускает DOCX и Astra inference. **Явный** запрос «Создай Word» и меню документов без входящего вложения оставлены для других задач. Аудит ZIP по умолчанию по-прежнему отправляет исходники текстовыми batches через Astra stream, без `/files`.

Признак обновления после рестарта: `[BOT BUILD] V188.120` и `[PROJECT AUDIT CONFIG] mode=multipass inputMode=text transport=stream concurrency=1`. Для аудита отправляй **настоящий файл `.zip`**, а не текстовый файл, в котором упоминается ZIP. Отправь один маленький тестовый ZIP с подписью «Гигорейв astra max, аудит проекта; верни итоговый ZIP», затем проверь `document-received → text-multipass-start → ai-batch-start`. Не должно быть «Готовлю Word-документ» или `input-bundle-built`.

Тесты: `npm run test:v188120`. Локальные тесты проверяют текстовый роутинг, поведение меню, runtime-отказ неправильного вложения и ранее реализованные stage checkpoint. Реальный Telegram/Astra end-to-end тест в этой среде не выполнялся. Новая отправка прежнего большого архива создаёт новый jobId и не продолжит прежний аудит.
