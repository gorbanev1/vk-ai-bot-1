# Исправление «тусы обновить будущие бф»: отдельная вкладка на каждый исходный URL

Режим `тусы обновить будущие бф` по-прежнему выбирает только ссылки из сохранённых будущих карточек без подтверждённой афиши; общий обход беседы 22 в этом режиме не запускается. Один и тот же URL двух карточек открывается один раз.

Браузерный этап для каждой такой ссылки теперь вызывает `openScraperTab`, который всегда создаёт новую вкладку через `context.newPage()` в существующем Chromium-контексте. Старая функция `openScraperPage` могла использовать пустую вкладку повторно. Другие вкладки не закрываются при открытии новой; собственная вкладка закрывается после полного захвата исходного поста и изображений, а данные сохраняются в кэш до обработки ИИ. Это **не** означает, что все вкладки останутся открыты до конца AI-анализа: память браузера защищена ограничением числа одновременно захватываемых страниц (8).

Исправлено также удержание browser-слота до конца AI: теперь слот освобождается по завершении захвата страницы, а AI продолжает работать в отдельной очереди. Поэтому медленный Vision не блокирует открытие следующей ссылки после паузы 5–16 секунд, за исключением ситуации, когда все 8 вкладок всё ещё заняты реальным захватом страницы. Пауза по-прежнему отсчитывается между запусками ссылок.

Команда `тусы обновить будущие` без `бф`, обычный `парсер все`, распознавание Astra, транзакции событий и политика подтверждения афиш не изменены. Работающие .env, SQLite, data, логи и профиль Chromium не включены в архив.

Добавлены проверки, что `бф` передаёт флаг отдельной вкладки по всей цепочке до `context.newPage()`, и что девятая ссылка открывается, даже если AI-анализ первой ещё не завершён. Это офлайн-тесты; реальный обход VK/Telegram и платные AI-вызовы не выполнялись.
