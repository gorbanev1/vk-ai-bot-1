ТЕХНИЧЕСКИЙ АУДИТ V188.141 → V188.142: ПОЧЕМУ «ПАРСЕР ВСЁ» ОТКРЫВАЕТ ЛИШЬ c22

ФАКТЫ, УСТАНОВЛЕННЫЕ ИЗ ВЛОЖЕННОГО РЕАЛЬНОГО КОДА V188.141

1. src/app/botApplication.js, функция getManualScraperSources(), составляет список из включённых Telegram HTML, VK public и VK-chat scraper-ов основного пула. Реестр берётся из runtime и .env. Число 16 со слов владельца; в доступном архиве нет его актуальной .env / runtime-снимка. Требуется сверить run.source-registry с 16 известными source ID.

2. В startAllManualScraperSources() V188.141 сортировка по autoScrollMessages перемещает VK chat c22 (автобэкфилл минимум 50) в начало массива. Следующие VK-источники используют priorVkCaptureWaiter.promise и только ПОСЛЕ его завершения ждут случайные 10–20 секунд. Если c22 не отдаёт onCaptureComplete, другие VK-функции даже не начинают открывать страницу. Это не 10–20 с между открытиями.

3. В startManualScraperSource() у полной команды для всех бесед V188.141 maxDurationMs=0, targetMessages=max(initialMessages, autoScrollMessages, 20). src/features/scrapers/sourceConfiguration.js задаёт для c22 по умолчанию initialMessages=300 и autoScrollMessages=50; src/platforms/vk/vkChatEventScraper.js считает историю только по РЕАЛЬНО старым stable CMID, а не по обычным 20 видимым сообщениям. Поэтому c22 способна долго крутиться, даже если на экране есть 20 постов. V188.141 убрала второй диагностический scroll, но не устранила этот штатный backfill и блокировку планировщика.

4. В общей команде onCaptureComplete / finishCaptureBarrier освобождает общий raw-cache barrier. Только ПОСЛЕ завершения всех raw-cache-источников запускается poster gate, затем admission/processing/AI/Vision. Это обеспечивает пакетную последовательность, но один незавершённый capture задерживает итоговые события даже когда другие источники уже запущены. Само отображение первого открытого окна не доказывает отсутствие 16 настроенных источников.

ИСПРАВЛЕНИЯ V188.142

A. Убрана сортировка источников по backfill. VK-старты идут с отдельным начальным gate и паузой 10–20 секунд от предыдущего VK-СТАРТА, не от его capture; Telegram остаётся на старом расписании. Любой ещё работающий c22 не задерживает открытие VK #2..#N.
B. Для c22 в «парсер всё» только: targetMessages=20 и disableHistoryBackfill=true. Полный capture остальных бесед сохраняет заданные им цели.
C. Для каждой беседы введён bounded finite pass (по умолчанию 180000 мс, можно переопределить через MANUAL_PARSER_CHAT_CAPTURE_MAX_MS); при достижении времени завершается capture после очередной браузерной операции, частичный результат помечается timedOut; дальше обрабатываются уже сохранённые данные. Остальные источники не исключаются.
D. На старте логируются число и ID всех реально зарегистрированных источников; если count !=16 в основном пуле, сохраняется mismatch с перечислением текущего реестра; код не придумывает недостающие настройки.
E. Существующие проверки картинок, AI/vision, запись событий, final dedupe и DOM checkpoint сохранены.

ПРОВЕРКИ И ОГРАНИЧЕНИЯ

`tests/scrapers/v188142AllSourcesLaunch.test.mjs` моделирует 16 VK-источников, у которых c22 не завершает capture: остальные 15 достигают START независимо от этого. Проверяет диапазон 10–20 с и исходный вызов orchestration. Тесты не используют авторизованный Chrome VK и не проверяют конкретный клиентский список 16 источников.

Для уверенной проверки на пользовательском компьютере нужны ровно два факта: `run.source-registry` / начальный вывод `[PARSER ALL SOURCES CONFIGURED]` и строки source.run.start / source.capture.complete из trace.jsonl за 2–4 минуты. Это покажет реальное число источников, были ли другие открытия, и где зависает конкретный source. При проблемах Chrome приложить также source.run.error.

ПРОМПТ ДЛЯ НЕЗАВИСИМОГО АУДИТОРА

Исследуй приложенный изменённый код V188.142, а не старый V188.135. Проследи команду «парсер всё»: получение всех runtime sources (ожидается 16 в основном пуле), изменение порядка, старт и интервал 10–20 с независимо от c22, открытие вкладок в общем persistent context, raw-cache onCaptureComplete, общий poster-gate/AI barrier, finite chat pass для c22, частичный timeout и onAdmissionComplete. Проверь, что ошибка одного источника не препятствует старту всех следующих и что event/image/vision/DB стадии не удалены. Не выдавай число 16 и успех живого VK-прохода за доказанные без .env / trace пользователя. Не предлагай отключить сбор всех источников или повторно запускать платный Astra аудит.
