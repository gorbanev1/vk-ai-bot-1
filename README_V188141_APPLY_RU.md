# Gigorave V188.141 — «парсер всё»: без повторной прокрутки для DOM-лога

## Исправленный дефект V188.140

В V188.140 после штатного конечного сбора сообщений VK-беседы запускался ВТОРОЙ обход истории только ради forensic DOM: до 300 шагов и ожидания на каждом шаге. Это задерживало завершение предыдущего источника, а значит и открытие следующего с настроенным интервалом 10–20 секунд. В V188.141 убрана добавочная навигация ради снимков для VK-пабликов, VK-бесед и публичных Telegram HTML-страниц. Штатный конечный сбор остаётся прежним; новое логирование само по себе не требует новых прокруток, дополнительных вкладок или повторного чтения истории.

## Как записывается DOM

При каждом УЖЕ СУЩЕСТВУЮЩЕМ считывании HTML штатным VK-парсером записываем первый полный DOM, затем новый checkpoint — если с предыдущего записанного прошло >=10 с и HTML изменился, ИЛИ текущий HTML вырос на >=30%. Не более 12 промежуточных полных снимков на источник. Никакого дополнительного таймера, параллельного чтения браузера и опроса во время простоя: 10 секунд проверяются только когда штатный парсер сам в очередной раз захватил DOM. Используется та же строка HTML, которая поступает в его точный контур.

`latest.dom.raw.html` **атомарно заменяется** последним записанным DOM. Нельзя дописывать новые `div` в конец HTML: это перестаёт быть браузерным DOM. Промежуточные полные версии сохраняются в `checkpoints/`, чтобы был виден ранний экран или подмена/виртуализация DOM; их можно не передавать для обычного анализа последнего снимка.

После штатного конечного захвата источника выполняется ОДНО финальное чтение открытой страницы **без прокрутки**. Главное `dom.raw.html` и `latest.dom.raw.html` обновляются финальным содержимым. `dom.structure.json`, `resources.json`, `page-state.json` и `manifest.json` относятся именно к финальному DOM. Если источник или вкладка закрылись до финального чтения, `dom.raw.html` может отсутствовать; последняя сохранённая промежуточная версия остаётся в `latest.dom.raw.html`. Наличие/отсутствие `manifest.json` отличает готовый эталон от незавершённого захвата.

Папка каждого источника:

```text
data/parser-forensic-archives/<runId>/
  trace.jsonl
  vk-dom-final-snapshots/
    chat-c22-<hash>/
      latest.dom.raw.html        # обновляется по мере ШТАТНОГО чтения DOM
      dom.raw.html               # финальный оригинальный DOM; главный файл
      page-state.json
      resources.json
      dom.structure.json
      pagination-progress.json  # фиксирует отсутствие дополнительной прокрутки
      manifest.json
      checkpoints/
        001.dom.raw.html
        002.dom.raw.html
        index.json
  poster-forensics/             # прежний forensic-журнал объявлений/афиш
```

`checkpoints/index.json` содержит время, причину снимка (`initial-observation`, `elapsed-10-seconds`, `growth-30-percent`), размер и SHA-256. Итоговый `manifest.json` содержит SHA-256 финального `dom.raw.html` и перечень checkpoints. Содержимое никогда не склеивается в синтетический HTML: последний снимок — единственное авторитетное состояние вкладки на момент финализации. Если VK удалил ранние сообщения из DOM, финальный снимок НЕ содержит их; ранние checkpoints помогают заметить этот факт, но не доказывают полноту всей истории.

## Установка и запуск

Останови бот после завершения текущих заданий. Сохрани резервную копию проекта и каталога `data/` (включая SQLite, `-wal`, `-shm` и картинки). Распакуй накопительный ZIP V188.141 в корень проекта **с заменой кодовых файлов**; свои локальные правки предварительно сравни. В архиве нет `.env`, базы, пользовательских фото или браузерного профиля. Не удаляй `data/`.

Запусти штатную команду «парсер всё» один раз. В `trace.jsonl` ищи `vk.native-dom.checkpoint` и `vk.final-fixture.persisted`; следующие источники должны открываться после завершения штатного capture и существующего планового интервала. Новая диагностика не содержит второго обхода беседы; если вкладка всё равно долго крутится, надо смотреть **штатный** `finite-history-backfill` и реальные `source.capture.*` сообщения, а не увеличивать лимиты финального слепка.

Офлайн-проверка готового слепка:

```bash
node scripts/vk-dom-final-verify.mjs "data/parser-forensic-archives/<runId>/vk-dom-final-snapshots/<source>"
```

Для разработки точного алгоритма по последнему состоянию передай сюда папку источника целиком. Достаточны `dom.raw.html`, `page-state.json`, `resources.json`, `dom.structure.json`, `manifest.json`; checkpoints добавляй, если нужно исследовать исчезнувшие по ходу парсинга посты. Полный HTML VK-бесед может содержать личную переписку и приватные ссылки — проверь архив перед передачей, не публикуй открыто.

## Что не делалось

Не переписывал правила отбора анонсов, vision или базу, не добавлял повторные переходы по источникам, не обещал полную историю из одного конечного DOM. На реальной VK-вкладке тест здесь не выполнялся; профильные тесты проверяют код и искусственные DOM-снимки.
