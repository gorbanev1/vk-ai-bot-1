# GIGORAVE V188.122 — сначала целый TXT, затем части только после явного отказа по размеру

Это патч поверх существующего рабочего проекта, а не самостоятельная установка. Остановите бот, сохраните резервную копию рабочей папки (включая `.env`, базы данных и `data/audit-jobs`) и наложите файлы архива поверх текущих исходников. Не удаляйте файлы, отсутствующие в этом ZIP. Затем запустите `npm start` и проверьте `[BOT BUILD] V188.122`.

**Исправлена ошибка V188.121:** прежний лимит 512 КиБ/150000 символов искусственно запрещал большие текстовые вложения ещё до запроса Astra. Теперь `.txt`/`.md` сначала локально загружается и целиком включается в ОДИН текстовый Responses stream-запрос Astra, без `/files`, `input_file`, Word, ZIP, Base64. Бот НЕ делит текст по размеру заранее.

Только если провайдер явно вернул ошибку размера запроса/контекстного окна (обычно HTTP 400/413/422, с соответствующей ошибкой), **и нет признаков начатой inference**, бот разрезает исходный текст на последовательные части примерно по 72 тыс. символов. Если отдельная часть явно отклонена по размеру, делит только эту часть пополам. Сохраняет последовательность и весь текст без пропусков и перекрытий. После получения ответов на все части пытается составить итоговое обобщение, а в один возвращаемый TXT обязательно включает **полные ответы на все части**, чтобы обобщение их не заменяло.

При timeout, обрыве stream, уже известном `responseId`, частичном ответе или другом неоднозначном исходе НЕ запускается новый полный запрос и НЕ начинается дробление: это могло бы повторить платный inference. В этих ситуациях бот сообщает о неудаче; для гарантированного восстановления незавершённого TXT-анализа нужен отдельный долговременный stage journal (в этой версии TXT-маршрут его ещё не имеет).

Локальный предохранительный лимит загрузки теперь 32 МиБ на один текстовый файл — это предел оперативной памяти обработчика, а не лимит контекста Astra. При превышении такого лимита понадобится потоковое чтение большого вложения в отдельной доработке. Поддержка реального полного запроса роутером не гарантирована локальными тестами.

## Логи

`[ASTRA TEXT ATTACHMENT STAGE] stage=full-request-start` → при успешном ответе `full-request-complete`; при явной ошибке контекста `context-rejected-splitting` → `part-complete` для каждой части → необязательная `synthesis-start`; затем один итоговый TXT через Telegram.
