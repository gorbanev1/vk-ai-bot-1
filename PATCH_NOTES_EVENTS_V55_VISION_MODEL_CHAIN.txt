Events V55 — vision model chain

1. Анализ входящих изображений больше не привязан по умолчанию к Terra. Без ключа запрос начинается с GPT_MODEL_DEFAULT / gpt-5.4-mini.
2. Явные ключи mini, gpt54, gpt55, pro/Luna, pro2/Terra и pro3/Sol выбирают стартовую модель анализа изображения.
3. Для vision-запроса строится последовательная цепочка:
   gpt-5.4-mini -> gpt-5.4 -> gpt-5.5 -> gpt-5.6-luna -> gpt-5.6-terra -> gpt-5.6-sol.
   При явном ключе цепочка начинается с выбранного уровня и идёт только вверх.
4. Каждая модель получает две попытки. После первого временного отказа бот ждёт случайно 5–30 секунд и повторяет тот же мультимодальный запрос без потери текста, картинок и reply-контекста.
5. После второго временного отказа, отсутствующей модели либо ответа 400 о неподдерживаемом image_url/multimodal content бот переходит к следующей модели цепочки.
6. Если отказала вся цепочка, техническое сообщение роутера, request id и тело ошибки в чат не публикуются. Пользователь получает короткое нейтральное уведомление; подробности остаются только в консоли.
7. Отдельные переменные GPT_VISION_MODE и GPT_VISION_MODEL больше не используются. Vision использует те же GPT_MODEL_DEFAULT/GPT_MODEL_GPT54/GPT_MODEL_GPT55/GPT_MODEL_PRO/GPT_MODEL_PRO2/GPT_MODEL_PRO3.
8. gpt-image-2 остаётся только генератором новых изображений и не участвует в распознавании входящей картинки.
9. Добавлен тест полного перехода через несколько неподдерживающих изображение моделей до первой успешной модели.

Миграция SQLite и новые зависимости не требуются.
