# GIGORAVE — согласование источников со сборкой STAGE6

Основой служит последняя STAGE6. Основные исходники присланного пользователем `vk-ai-bot(6).zip` были побайтово идентичны исходникам STAGE6, поэтому старые исправления не применялись повторно.

## Минимальные изменения

- `src/features/scrapers/scraperCommandRouting.js`: команда `тусы удалить источник vk:имя` / `тусы удалить источник tg:канал` и варианты для второстепенного пула. Это действие с источником, не с мероприятием.
- `src/app/botApplication.js`: обработчик этой owner-only команды. Удаляется ТОЛЬКО сохранённая владельцем запись из выбранного SQLite-реестра и соответствующий runtime-скрейпер; прежние источники/события/ledger не трогаются.
- Запрещено удалять источник во время выполняющейся операции парсера, второстепенного автопрохода или активной VK-беседы. Для источника из `.env`, обязательной или стандартной конфигурации выводится точная ошибка вместо ложного «удалено».
- `tests/scrapers/ownerRemoveSourceSafety.test.mjs`: маршрутизация, owner-guard, изоляция пулов, реальное удаление из runtime-списка и реестра, запрет активного/постоянного источника.

## Точное использование

Сначала команда `тусы парсер`, чтобы увидеть постоянные идентификаторы. Затем в ЛС владельца: `тусы удалить источник vk:имя` или `тусы удалить источник tg:канал`. Для второстепенного пула: `тусы быдлячьи удалить источник vk:имя`. Номер позиции в списке не является ID. Команда удаляет источник из дальнейшего сканирования, но не прошлые публикации и события.

## По сообщению «открылись только пять источников»

В КОПИИ присланной SQLite основной owner-registry содержит 5 VK Public источников, во второстепенном owner-registry нет дополнительных. Это НЕ равно полному списку: `getManualScraperSources()` также включает источники `.env`, обязательные VK и беседы при включённых флагах. В архиве нет действующей `.env` и живого лога `parser-all`, поэтому точную причину открытия лишь пяти вкладок по ним установить нельзя. Проверить `[PARSER ALL SOURCES CONFIGURED] count=... ids=...`, затем для каждого ID `[PARSER ALL SOURCE OPEN START]` или `[PARSER ALL SOURCE FAILED]`.

## Не изменено

Astra: длительность ожидания, SSE-трассировка, восстановление и анти-дубль платного POST. Весь event pipeline, source→events→ledger, verified snapshot, дедупликация и правила дат сохранены побайтово.

`node scripts/check-syntax.mjs`, `node scripts/check-imports.mjs`, `node scripts/check-named-imports.mjs` — успешны. 7/7 тестов источников, 16/16 тестов событий (выбранные неустаревшие тесты) — успешны. В старом `eventSnapshotFreshnessV184.test.mjs` сохранено устаревшее ожидание версии snapshot 7: фактическая версия уже 8, этот тест не менялся. Реальные сайты, AI и рабочая SQLite не запускались; исходные `.env`, SQLite, `-wal`, `-shm`, пользовательское `data/` в архив не включены.

Установка: сохранить рабочие `.env`, `data/`, все SQLite и `-wal`/`-shm`; заменить только исходники проекта. НЕ заменять/удалять текущую БД.
