# Руководство разработчика

## Требования

- Node.js 24.x.
- pnpm 10.17.x.
- Windows 10/11 либо Linux.
- Установленный Chrome, Chromium или Edge для видимых Playwright-вкладок.
- Для реального запуска: токены VK, Telegram и GPT-router.

## Установка

```bash
cp .env.example .env
pnpm install --frozen-lockfile
pnpm verify
```

В PowerShell вместо `cp`:

```powershell
Copy-Item .env.example .env
```

## Запуск

```bash
pnpm dev      # node --watch
pnpm start    # обычный запуск
```

При запуске ожидаются строки:

```text
[BOT PATCH] events-v52-reply-target-analysis
[TELEGRAM BOT STARTED] ...       # если задан токен
Запускаю VK Long Poll…
Бот запущен...
```

## Проверки

```bash
pnpm check:syntax   # node --check для src/tests/scripts
pnpm check:imports  # все относительные импорты существуют
pnpm test           # unit и database tests
pnpm verify         # все проверки подряд
pnpm stats          # количество файлов и строк
```

`pnpm verify` обязателен перед созданием патча.

## Как добавить новую команду

1. Если это чистый разбор текста, создать routing-модуль в соответствующем `features/*`.
2. Вернуть объект, а не сразу отправлять сообщение:

```js
{
    matched: true,
    action: 'enable',
    value: 10,
}
```

3. Написать unit-тест для вариантов команды и ложных срабатываний.
4. В `botApplication.js` добавить только вызов обработчика и платформенную отправку.
5. Обновить `PUBLIC_COMMANDS.txt` и `docs/BEHAVIOR_AND_COMMANDS.md`.

Не размножать регулярные выражения одной команды по VK и Telegram: обе платформы должны приходить в один общий обработчик.

## Как добавить новую GPT-модель

1. Добавить model id в `.env.example`.
2. Дополнить `DEFAULT_GPT_MODEL_IDS` и `gptModeSettings` в приложении.
3. Дополнить aliases в `features/ai/gptModeRouting.js`.
4. Решить дневной лимит и профиль длины.
5. Добавить тесты routing.
6. Проверить, что image-модель не проходит как текстовая.
7. Обновить помощь.

## Как добавить новый источник событий

1. Создать platform scraper либо переиспользовать существующий.
2. Источник обязан вернуть исходный текст, URL, дату публикации и изображения.
3. До GPT применить `eventCandidateRouting`.
4. После GPT применить `eventValidation`.
5. Сохранять source row и event row транзакционно.
6. Подключить dedupe при общей выдаче.
7. Не включать автоматический браузерный запуск без отдельного требования.

## Как изменить схему SQLite

1. Не редактировать старую таблицу так, будто базы ещё нет.
2. Добавить `CREATE TABLE IF NOT EXISTS` для новой таблицы.
3. Для нового столбца существующей таблицы использовать мягкую миграцию через проверку `PRAGMA table_info`.
4. Дать безопасный default.
5. Написать тест, который импортирует модуль на старой структуре либо проверяет новое поле.
6. Не класть рабочую `bot.sqlite` в патч.

## Комментарии в коде

Комментарии нужны там, где без них junior может принять неверное архитектурное решение:

- почему используется один процесс;
- почему вкладка не закрывается;
- почему память изолирована по `peer_id`;
- почему `warmth` не равна API `temperature`;
- почему pro-астрология не использует локальный пакет;
- почему событию одновременно нужны суть, дата и место;
- почему запрос возвращается в лимит при сетевой ошибке.

Не комментировать очевидное:

```js
// Увеличиваем count на 1
count += 1;
```

Лучше объяснять причину:

```js
// Счётчик хранится в БД, иначе после перезапуска бот снова ответит раньше 10-го сообщения.
count += 1;
```

## Стиль кода

- ESM, расширение `.js` в относительных импортах.
- Четыре пробела.
- Ранний `return` вместо глубоких вложений.
- Чистые routing-функции не читают базу и не отправляют сообщения.
- Внешние ошибки логируются безопасной структурой.
- Секреты, data URI и URL не отправляются в ЛС-диагностику.
- Значения из `.env` ограничиваются и валидируются.
- Время хранится как Unix seconds, календарные даты — `YYYY-MM-DD`.

## Подготовка релиза

1. Скопировать текущую рабочую версию в новую папку.
2. Изменить `BOT_PATCH_VERSION`.
3. Выполнить `pnpm verify`.
4. Проверить импорты и отсутствие секретов.
5. Собрать patch только из изменённых файлов.
6. Собрать source archive без `.env`, `data/bot.sqlite`, браузерного профиля и `node_modules`.
7. Проверить архив распаковкой.
8. Записать SHA-256.
9. Обновить `PROJECT_MANIFEST.json` и patch notes.

## Правило безопасного рефакторинга

Сначала перенос без изменения логики, затем функциональное изменение. Не совмещать в одном патче:

- перенос 2 000 строк между файлами;
- изменение маршрутизации;
- миграцию базы;
- новый внешний API.

Иначе по логу невозможно понять, что именно сломалось.
