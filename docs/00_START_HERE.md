# С чего начать разработчику

## Что это за проект

Gigorave — один Node.js-процесс, который одновременно:

- принимает сообщения VK Long Poll;
- принимает Telegram updates через long polling;
- маршрутизирует запросы между шестью текстовыми GPT-моделями;
- получает потоковые SSE-ответы и изображения `gpt-image-2`;
- хранит историю групп, явную память, настройки общения и афишу в SQLite;
- вручную открывает браузерные источники VK/Telegram через Playwright;
- вычисляет максимальный локальный пакет джйотиш с аудитом покрытия;
- позволяет принудительно включить локальные эфемериды для `pro/pro2/pro3` ключом `локалэфемериды`, `локал` или `расчёт локально`;
- выполняет фоновые задачи персонализации, очистки событий и общения.

Это модульный монолит: один процесс и одна база, но код разделён по предметным областям. Для текущего масштаба это проще и надёжнее микросервисов и Kubernetes.

## Текущая версия

```text
events-v104-event-quality-proposals-reparse
```

V104 сохраняет non-destructive dedupe V103 и добавляет полный контур качества существующей афиши: публичные предложения тус с 24-часовой owner-модерацией, повторное добавление той же ссылки через подтверждённое обновление, точный выбор фото из VK wall-post, массовый owner-reparse `тусы перепарсить ссылки`, удаление/возврат событий и единые Telegram media-card сообщения без отдельной картинки перед текстом. Старый verified-event snapshot автоматически пересобирается по актуальной dedupe-логике.

V103 добавляет non-destructive event dedupe registry. `тусы дубли проверить` делает глубокий dry-run по всем четырём event-таблицам SQLite, а `тусы дубли применить` записывает canonical/duplicate membership в `event_dedupe_groups` и `event_dedupe_members`, после чего пересобирает V2 snapshot. Сырые event-строки остаются evidence и не переводятся в `ignored`. `тусы проверить` и финальная проверка после парсера обновляют тот же canonical registry автоматически.


V109 добавляет пост-ивентную кампанию отзывов «Пересоздания». `разослать всем пересоздание` готовит встроенный шаблон для всех личных адресатов из реестра запросов координат; `пересоздание отправить` реально рассылает. Следующее обычное сообщение успешно получившего пользователя сохраняется как отзыв и пересылается владельцу. `пересоздание отзывы` и `пересоздание отзывы статус` читают сохранённые результаты. ## Что нельзя делать без отдельного решения

- Не запускать две копии бота с одной базой.
- Не удалять совместимые файлы `src/*.js`, пока все внешние импорты не переведены.
- Не заменять SQLite на PostgreSQL «заодно» с функциональным патчем.
- Не включать автоматическое открытие всех браузерных вкладок при старте.
- Не коммитить `.env`, `data/bot.sqlite`, браузерный профиль и скриншоты.
- Не менять маршрутизацию натала и прашны без тестов обеих веток.
- Не ослаблять строгую проверку событий до одного признака вроде времени сообщения.
