# Поведение продукта и команды

Полный публичный текст справки находится в `PUBLIC_COMMANDS.txt`. Этот документ описывает внутренние правила, которые важно не потерять при переносе.

## V104: афиша — предложение, обновление, reparse и удаление

- Telegram: `➕ Предложить тусу` → бот просит ссылку или текст → нормализует карточку → отвечает, что материал отправлен на модерацию.
- VK: `предложить информацию о тусе` запускает тот же двухшаговый сценарий.
- Owner получает заявку в личку VK и Telegram. `да <id>` публикует, `нет <id>` отклоняет; при единственной ожидающей заявке допустимы просто `да`/`нет`. Через 24 часов без решения заявка публикуется автоматически.
- Повторный owner-add той же source URL сначала спрашивает `Хотите обновить информацию?`; `да` reparses source и заменяет активную manual-карточку.
- `тусы перепарсить ссылки` перечитывает будущие активные события по исходным ссылкам во всех event-таблицах, обновляет чистые поля/картинки и затем пересобирает dedupe + verified snapshot. Неоднозначные multi-event source URL пропускаются и попадают в отчёт.
- Для VK wall URL фото выбирается из attachment самого поста. VK API media имеет приоритет над DOM; avatar/logo/icon/UI-кандидаты отбрасываются, а `og:image`/link preview используются только fallback при отсутствии post photo.
- `тусы удалить <название>` / `тусы убрать <название>`: точное или ≥93% fuzzy-сопоставление удаляет событие и показывает команду/кнопку возврата; более слабый единственный кандидат сначала требует `да`/`нет`.
- Карточка события отправляет ровно одну лучшую афишу. Telegram использует один media message с caption; VK также не отправляет галерею из нескольких картинок. Если у старой VK-записи нет локального imagePath, бот сначала пробует восстановить фото по точному wall URL и только затем генерирует карточку-заглушку.
- После `🎉 Тусы` Telegram показывает период и предупреждение: `(Пока что может работать немного через жопу. Допилю, когда вытащу руки из жопы.)`.

## Модели

| Ключ | Модель | Типичный ответ |
|---|---|---|
| без ключа / `mini` / `мини` / `база` / `эконом` | `gpt-5.4-mini` | не более пары средних абзацев |
| `gpt54` / `стандарт` | `gpt-5.4` | короткий базовый профиль |
| `gpt55` / `классик` | `gpt-5.5` | короткий базовый профиль |
| `pro` / `луна` | `gpt-5.6-luna` | глубокий режим, до двух больших страниц |
| `pro2` / `терра` | `gpt-5.6-terra` | глубокий режим, до двух больших страниц |
| `pro3` / `сол` | `gpt-5.6-sol` | глубокий режим, до двух больших страниц |

`подробно` расширяет обычный ответ. Натал всегда получает развёрнутый профиль независимо от модели. Обычная прашна без ключа остаётся краткой; слова `подробно`, `глубокий разбор`, `максимальный техрасчёт` или любой режим `pro/pro2/pro3` включают полный технический разбор без лимита в 2–3 абзаца и 10 положений.

Для `pro`, `pro2` и `pro3` действует единый контракт на обеих платформах:

- ответ может занимать до двух больших страниц и автоматически делиться на несколько нативных reply-сообщений;
- обычное правило 8–10 предложений и лимит одного сообщения платформы не ограничивают весь pro-ответ;
- если пользователь просит 10 000 слов, восемь страниц или иной заведомо больший объём, бот не спорит о длине и не просит выбрать формат, а молча выдаёт лучший законченный вариант в пределах двух страниц;
- короткая мета-отписка о том, что текст «не влезает», автоматически распознаётся и один раз перегенерируется с исправленным контрактом.

`gpt-image-2` создаёт изображения. Текстовая модель может готовить промпт, но сама картинка всегда идёт через image-модель.

## Натал и прашна

### Явный локальный ключ

Для обоих типов запросов работают эквивалентные ключи:

- `локалэфемериды`;
- `локальные эфемериды`;
- `локал`;
- `расчёт локально` / `рассчитай локально`.

Ключ можно поставить в любом месте команды. Он принудительно включает локальный расчёт и для `pro`, `pro2`, `pro3`:

```text
Гигорейв pro3 натал локалэфемериды 14.03.1987 19:40 Воронеж подробно
Гигорейв pro2 прашна расчёт локально Москва вопрос...
```

### Маршрутизация

- `mini/gpt54/gpt55`: локальный `maximum` по умолчанию;
- `pro/pro2/pro3`: model-only по умолчанию, но явный локальный ключ переключает их на `maximum`;
- `нелокал`, `без локального расчёта`, `не считай локально`: model-only для любой модели и имеют приоритет над словом `локал`.

Любой локальный маршрут имеет контракт:

```text
localCalculation=true
packet=maximum
```

Сокращённые `fast`, `balanced` и прежний `full` для локального натала/прашны не выбираются. В модель передаётся `gptPayloadMaximum` без скрытой обрезки рассчитанных полей.

### Состав максимального пакета

Локальный движок считает и упаковывает доступные Swiss Ephemeris/Moshier данные: тропические и Lahiri-сидерические положения, геоцентрические/топоцентрические/экваториальные/горизонтальные координаты, скорости и расстояния, явления диска, орбитальные элементы, узлы и апсиды, восход/заход/транзиты, доступные системы домов, Whole Sign, панчангу с границами, аспекты и угловую матрицу, достоинства, сожжение, чара-караки, парашари-дришти, арудха-пады, Vimshottari маха/антар/пратьянтар-даши и математические D1–D60.

Перед вызовом модели выполняется аудит. Обязательное ядро должно быть полным; иначе запрос падает с диагностикой вместо ответа «от фонаря». Недоступные астероиды, звёзды, отдельные дома или системы координат перечисляются в `optionalGaps` и предупреждениях. Аудит вместе с пакетом передаётся модели.

### Точность эфемерид

- С корректным `EPHEMERIS_PATH`, содержащим `*.se1`, запрашивается `SEFLG_SWIEPH`.
- Движок проверяет фактический return flag каждого основного `calc_ut`, а не только наличие файлов. Полностью подтверждённый режим получает `precision=swiss-files-confirmed`.
- Без подтверждения Swiss для всех прямых основных тел аудит ставит `precision=moshier-or-mixed-fallback` и перечисляет тела в `optionalGaps.nonSwissDirectPrimaryBodies`.
- `ASTROLOGY_REQUIRE_SWISS_FILES=1` запрещает fallback и останавливает локальный запрос, если файлов нет или фактические return flags не подтверждают Swiss для всех основных тел.

Для локального натала часовой пояс определяется по месту и дате рождения. Если надёжно определить его нельзя, бот просит IANA-пояс и не подставляет `Europe/Moscow` молча.

### Граница понятия «всё»

`maximum` означает все поля, реально реализованные и рассчитанные текущим движком, без сокращённого LLM-профиля. Это не ложное заявление, что реализованы все школы джйотиш. D1–D60 сейчас являются математическими гармоническими проекциями; специальные правила каждой традиционной варги, полный Shadbala, Ashtakavarga и исчерпывающий каталог йог отдельно не заявляются и не должны выдумываться моделью.

### Видимость технического пакета

Координаты, полный JSON/пакет и хеш не публикуются отдельными сообщениями. Они остаются в диагностике и передаются выбранной модели; пользователь получает название модели и готовую интерпретацию.

### Разделение типов

Слова `натал`, `натальная карта`, `natal`, `birth chart` не должны маршрутизироваться как прашна. Прашна — карта момента вопроса; натал — карта рождения. Натал всегда получает развёрнутый профиль; краткость обычной прашны меняет объём интерпретации, но не объём локального расчёта.

## Неизвестные термины

Перед основным GPT-запросом дешёвая модель может выделить нестандартные слова, локальные мемы и редкие сокращения. Затем определения ищутся только в явной памяти текущего `peer_id` и подмешиваются в повторный запрос. Обычные слова `натал`, `джйотиш`, `натальная карта` не считаются неизвестными.

## Явная память

Сохранение поддерживает формы:

- `запомни`, `запоминай`, `запомнить`;
- `запиши/сохрани/добавь/внеси в память`;
- `зафиксируй в памяти`, `держи в памяти`, `помни`.

Удаление:

- `забудь`, `распомни`, `раззапомни`;
- `удали/сотри из памяти`;
- `очисти/почисти память`;
- `не помни больше`.

Удаление логическое: `active=0`. Это tombstone, чтобы исторический backfill не восстановил забытую запись.

## Афиша

Источники не запускаются автоматически. Ручные source IDs:

- `tg:kurazhcity`;
- `vk:rb_diesel`;
- `vk:overlockbar`;
- `chat:2000000022`;
- `chat:2000000003`;
- `chat:2000000014`.

Периоды кнопки «Тусы»:

- ближайшие дни с захватом выходных;
- эти выходные;
- две недели;
- месяц;
- все будущие тусы.

События объединяются между Telegram, VK-пабликами, VK-беседами и ручными записями. Предпочитается публичная ссылка источника. Личная ссылка на сообщение беседы не публикуется; используется найденная публичная ссылка либо подпись «Информация с беседы».

## Ручное добавление события

Только владелец:

- Telegram: owner-кнопка;
- VK: команда `добавить событие <текст или ссылка>`.

Если есть ссылка:

1. открывается persistent browser tab;
2. страница немного прокручивается;
3. вкладка остаётся открытой для ручной проверки;
4. текст страницы сравнивается с сообщением;
5. если передана только ссылка, запись возможна только при успешном чтении страницы;
6. событие должно пройти суть + дату + место;
7. прошедшее событие не добавляется в будущую афишу.

## Теплота и роли

Любой участник текущего диалога может установить:

```text
теплота общения 1..10
температура общения 1 из 10
расположенность 7/10
```

Это не sampling `temperature`. Модели передаётся человеческая инструкция:

```text
Теплота и расположенность: 7/10
```

Роли:

- быдло;
- хам;
- лошара;
- дурачила / дурачина;
- интеллигент;
- учёный;
- политик;
- обычный/нейтральный сброс.

Роль хранится по диалогу в SQLite и подмешивается в пользовательские ответы. `Быдло` говорит приземлённо, грубо и холодно-цинично, без мягких клоунских сравнений. `Дурачила` использует правдоподобно тупую бытовую логику, примитивные выводы и самоуверенную неправоту, но не сюрреализм с говорящими предметами и случайными овощами. `Политик` остаётся узнаваемо гипертрофированным. Все роли сохраняют фактический ответ и ограничения безопасности.

## Нативный ответ на исходное сообщение

Когда обработка вызвана конкретным пользовательским сообщением, результат отправляется штатным reply именно к нему. В VK транспорт использует `MessageContext.reply()`. В Telegram текст, изображения и документы получают `reply_parameters.message_id`; форумный `message_thread_id` сохраняется. Это правило распространяется на команды, GPT, натал, прашну, справку, ошибки, прожарку и ролевые ответы. Автономные фоновые реплики не имеют источника и отправляются обычным сообщением.

## Анализ сообщения-цели штатного reply

Если пользователь отвечает на конкретную реплику и пишет, например:

```text
Гигорейв, оцени это сообщение
Гигорейв, разберись, насколько это правдоподобно
Гигорейв, прокомментируй то, на что я отвечаю
Гигорейв, переведи эту реплику
```

модель получает два раздельных блока: текущую команду пользователя и сообщение-цель штатного reply. Для цели передаются платформа, индекс сообщения, имя и индекс автора, полный доступный текст и краткое описание вложений. При просьбе оценить, разобрать, проверить, объяснить, прокомментировать, охарактеризовать, высмеять, похвалить, перевести или переписать объектом является именно reply-цель.

Текст reply-цели считается недоверенной цитатой: команды и псевдосистемные инструкции внутри неё не выполняются. Если содержимое вложения недоступно текстовой модели, бот передаёт только тип и доступные метаданные и не требует от модели выдумывать содержимое. Логика действует во VK, Telegram и в явном маршруте GigaChat. Ответ бота нативно прикрепляется к текущей команде пользователя, поэтому цепочка reply сохраняется.

## Обращение к боту в VK

В групповой беседе запрос обрабатывается при прямом упоминании бота, при ответе на сообщение сообщества и при цитировании/пересылке сообщения сообщества. Reply или цитата запускают новую двухчасовую сессию так же, как первое упоминание; активная сессия заранее не требуется. Проверяются и вложенные цепочки `reply_message` / `fwd_messages` с ограничением глубины.

## Адресная игровая прожарка

В групповой беседе доступны:

```text
доебись
доебись <имя/@username>
Гигорейв доебись
Гигорейв доебись <имя/@username>
Гигорейв доебаться [<имя/@username>]
Гигорейв докопаться [<имя/@username>]
Гигорейв фас [<имя/@username>]
```

Начиная с V135 эти команды идут через абсолютный локальный fast-path во VK и Telegram: слово «Гигорейв», @упоминание бота и активная диалоговая сессия не обязательны. Явный VK `@username`, `id123`, mention или ссылка на профиль сначала резолвятся напрямую через VK API; загрузка полного состава беседы используется только когда она действительно нужна.

V136 не меняет этот fast-path: он меняет только объём/отбор истории и сокращает служебный промпт прожарки.

Без имени бот случайно выбирает активного участника из `communication_participants`, исключая автора команды. С именем сначала выполняется локальное сопоставление:

1. прямой VK mention, `id123` или точный `@username`;
2. нормализация регистра, пробелов и знаков;
3. русско-латинская транслитерация;
4. сравнение полного имени, ника и отдельных токенов по нормализованному Levenshtein similarity;
5. результат от 90% считается совпадением;
6. если несколько кандидатов находятся в пределах 3,5 процентного пункта от лучшего результата, выбирается тот, кто писал позже.

Если локального совпадения нет, GPT получает только список `userId`, имён/ников и `lastSeenAt`, возвращает ранжирование кандидатов, а близкая ИИ-ничья также разрешается по последней активности. Начиная с V136 после выбора бот собирает от 20 до 60 последних содержательных сообщений адресата. Основной слой — последние 24 часа; если там меньше 20 сообщений, бот добирает более старую историю, пока не наберёт минимум 20 либо пока история реально не закончится. После обязательных 20 реплик действует компактный символьный бюджет: короткие сообщения позволяют добрать до 60, длинные не раздувают запрос. Команды прожарки и пустые сообщения исключаются.

Прожарка может быть резкой, разговорной и ситуативной, но не должна содержать угрозы, призывы к коллективной травле, доксинг, сексуальное унижение, реальные обвинения, диагнозы или нападки по защищённым и личным признакам. На беседу действует короткий cooldown, на конкретного адресата — двухчасовой cooldown; команда не запускает бесконечную перепалку.

## Фоновые реплики и перепалка

Только роли `быдло` и `дурачила` в группах получают случайный следующий запуск через **1 минуту–1 час**. Проверка расписания идёт раз в минуту, фактическое время хранится в SQLite. При первом старте V45 старые будущие расписания длиннее часа автоматически переносятся внутрь нового окна.

Каждый запуск выбирает один сценарий:

- **вся беседа — 40%**: модель получает недавний транскрипт, выделяет реальную тему, противоречие или общий тон и отвечает без обращения к конкретному человеку;
- **в воздух — 40%**: самостоятельная приземлённая грубая реплика без имени и без ссылки на контекст;
- **участник — 20%**: выбирается недавний участник, модели передаются его последние содержательные сообщения за сутки, а ответ обращается к нему по имени.

Все три сценария сначала генерируются случайно выбранной Luna (`pro`) или Terra (`pro2`) с вероятностью 50/50. Локальные шаблоны используются только как аварийный fallback при ошибке или пустом ответе модели. Выкрики не запускаются в полностью мёртвом чате: требуется хотя бы один участник за последние 72 часа.

Для `быдло` промпт требует максимально грубую, наглую и холодно-циничную манеру в допустимых пределах, с привязкой к реальным словам и без выдуманных фактов. Для `дурачила` требуется откровенно тупая, примитивная, грубая и самоуверенно неправильная логика без сюрреалистической клоунады.

Перепалка сохраняется только после адресного сценария `участник`. Если этот участник отвечает выпадом, продолжение тоже случайно использует Luna или Terra. Перепалка завершается при нормальном сообщении либо таймауте. Запрещены угрозы, пожелания вреда, реальные обвинения, преследование, доксинг, сексуальное унижение и выпады по защищённым или интимным личным признакам.

## Восстановление GPT-запроса V47

## V103: глубокий аудит и canonical registry афиши

Только owner:

```text
тусы дубли проверить
сканировать базу тус на дубли
тусы дубли применить
```

`тусы дубли проверить` ничего не меняет. В V148 это быстрый локальный проход без GPT: команда читает будущие `approved/pending` строки из `telegram_events`, `vk_events`, `vk_chat_events`, `manual_events`, делает локальную нормализацию, индекс кандидатов и deterministic/final dedupe. Состояние и результат сохраняются в `maintenance_state`, поэтому зависший старый запуск больше не выглядит бесконечно работающим.

`тусы дубли статус` показывает `running/completed/failed/interrupted`, текущий этап, прогресс, число строк/канонических событий/дублей и время последнего прохода. Перезапуск процесса переводит незавершённый `running` в `interrupted`.

`тусы дубли применить` сохраняет результат быстрого прохода в `event_dedupe_groups`/`event_dedupe_members` со scope `all-db`. Сырые строки событий остаются неизменными. Verified snapshot инвалидируется и перестраивается уже в фоне, поэтому команда не ждёт GPT-пересборку.

`тусы проверить` и final verification после парсинга сохраняют registry со scope `configured` и V3 canonical snapshot. Быстрый legacy-аудит `проверить тусы на совпадения` остаётся read-only.

Verified snapshot version = 3 и дополнительно содержит `dedupeAlgorithmVersion`. Snapshot любой старой версии или другого dedupe-алгоритма после V107 не используется. При отсутствии валидного V3 snapshot обычный запрос применяет полный deterministic two-contour без сетевых AI-вызовов.

## V101: полный текст координат и правил

В активном публичном окне, а для owner — в любое время при включённом режиме, `координаты`, `корды`, `карды` и варианты `... пересоздание` возвращают одно сохранённое сообщение. V101 один раз устанавливает в него координаты `51.691730, 39.251385`, добровольный donation notice, правила мероприятия, старт 17:00, возможность прийти раньше и ссылку `https://vk.ru/peresosdanie` на случай изменений. После этого owner может заменить сообщение обычной командой `корды сообщение`; миграция больше не повторяется.


## V108: QR-код поддержки

Публичные команды `куаркод`, `куар код`, `qr`, `qr код`, `qr-код` возвращают QR-код поддержки. Каноническая подпись при первом запуске: `89968257889 Сбер Игорь Анатольевич.`. Если картинка настроена, подпись и картинка отправляются одним media-сообщением и во VK, и в Telegram.

Только владелец может выполнить `заменить сообщение куаркод`. Следующее сообщение в том же диалоге обрабатывается атомарно: текст без изображения меняет только подпись; текст с изображением — подпись и QR; изображение без текста — только QR. Срок ожидания — один час. Картинка ограничена 10 МБ и сохраняется в `data/qr-code/`; текущий относительный путь и текст находятся в SQLite.

## V118 owner AI audit

`Гигорейв тест всех моделей` — полный фоновый live-аудит всех поддерживаемых AI-ключей из `.env`. Проверяются каталоги каждого ключа, все распознанные text/chat модели и все найденные image-generation модели. Итоги отправляются владельцу, полный лог сохраняется в `AI_FULL_AUDIT_RESULTS/<timestamp>/`, а рабочий SQLite-реестр `ai_runtime_modes` пересобирается только из успешных комбинаций. `parsed_secrets.txt` runtime больше не читает.

Telegram-команды `/start`, `/menu`, `/home`, `главная`, `главное меню`, `домой` и кнопка `🏠 На главную` всегда возвращают основную reply-keyboard до любого application-state/router.


## V123: Telegram Pinball Mini App (legacy)

Исторически V123 добавляла `🎮 Пинбол`. Начиная с V139 функция снята с runtime: кнопки в Telegram-меню нет, специальной маршрутизации `пинбол`/`pinball` нет, встроенный pinball HTTP-server при старте приложения не запускается. Исходники Mini App и старая таблица рекордов оставлены как legacy-данные, чтобы релиз не удалял пользовательскую историю.

Игра поддерживает клавиатуру (`A/←`, `D/→`, `Space`, `Q/W/E`, `P/Esc`, `R`) и touch controls. Онлайн-score принимается только после валидной Telegram Mini App session, полученной по HMAC-проверенному `initData`.

## V123: targeted AI third round и `.env` cleanup

`Гигорейв тест всех моделей` не тестирует GigaChat и owner `OPENAI_COMPAT_API_KEY`. После provider-aware первых двух кругов V123 адресно повторяет только неоднозначные text FAIL. Содержательный HTTP/SSE ответ считается доказательством рабочего транспорта даже без дословного audit-marker; instruction compliance хранится отдельно. ## V148 — статистика обращений

Владелец может использовать `обращения сегодня`, `обращения неделя`, `обращения 3 дня`, `обращения за прошлые 4 дня` и аналогичные интервалы. Прямые обращения в VK и Telegram считаются отдельно по источнику; групповые обращения тоже пишутся, но выводятся только справочно. В 18:00 и 21:00 по Москве владелец получает накопительный отчёт за день. Выполненные слоты сохраняются в SQLite, поэтому рестарты не создают повторные отчёты. Текст сообщений в статистику обращений не копируется.

## V148 — досье

Функция досье теперь сначала собирает доказательную базу из сохранённых фактов и репрезентативной выборки собственных сообщений пользователя, затем просит GPT сформировать структурированный поведенческий портрет. Формат отделяет установленные факты от аналитических гипотез, указывает уверенность и описывает коммуникацию, конфликт, интересы, навыки, социальную роль, решения и динамику. Медицинские диагнозы, чувствительные признаки, криминальные обвинения и выводы о преступном намерении запрещены.
