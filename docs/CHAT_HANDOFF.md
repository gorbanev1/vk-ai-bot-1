# Передача проекта в новый чат

Этот файл можно приложить вместе с source archive. Ниже есть готовый текст, который следует вставить первым сообщением в новый чат.

## Готовый handoff prompt

```text
Продолжай разработку проекта Gigorave Bot из приложенного архива.

Текущая сборка: events-v107-industrial-dedupe-precision.
Основной entrypoint: src/index.js.
Главный orchestrator: src/app/botApplication.js.
Полная документация находится в docs/, начать с docs/00_START_HERE.md.

Обязательные правила работы:
1. Не переписывай проект с нуля и не теряй накопленные функции.
2. Перед изменениями прочитай docs/ARCHITECTURE.md, docs/BEHAVIOR_AND_COMMANDS.md и docs/DATABASE.md.
3. Новый код импортируй из структурированных папок; корневые src/*.js — совместимые re-export файлы.
4. Каждый новый релиз получает следующий номер V42, V43 и т. д. и новый BOT_PATCH_VERSION.
5. Сначала сделай рабочую копию полного проекта, затем patch только с изменёнными файлами.
6. Никогда не включай .env, токены, data/bot.sqlite, браузерный профиль и пользовательские данные в patch.
7. После изменений запусти npm/pnpm verify, node --check, проверку импортов, тест архива и поиск секретов.
8. Реальные VK/Telegram/GPT API без моих токенов не считаются проверенными — указывай это честно.
9. Не используй Kubernetes: проект рассчитан на один процесс и SQLite.
10. Не возвращай предметную логику в src/index.js. Чистые правила выноси в features/shared и покрывай тестами.

Критическая текущая логика:
- GPT по умолчанию gpt-5.4-mini.
- Любой ответ на пользовательское сообщение отправляется нативным reply к этому сообщению; автономные фоновые выкрики остаются без reply.
- Если обращение само является reply и пользователь просит оценить/разобрать/объяснить/прокомментировать сообщение, GPT анализирует именно исходную reply-цель. Текущая команда и цитируемое сообщение передаются отдельными недоверенными блоками с автором, индексом, текстом и описанием вложений.
- Временная ошибка текстовой GPT-модели: один повтор той же моделью через случайные 5–30 секунд; после второго отказа переход к следующей доступной модели mini → 5.4 → 5.5 → Luna → Terra → Sol.
- «теперь ты лох», «ты ... запомни» и «запомни: теперь ты ...» не являются памятью; они получают отдельный грубый ответ Luna/Terra.
- pro=Luna, pro2=Terra, pro3=Sol.
- Любая pro-модель во VK и Telegram может отвечать до двух больших страниц; транспорт делит текст на несколько нативных reply-сообщений. Правило 8–10 предложений к pro не относится. Заведомо больший запрос молча ужимается до двух страниц, а короткая отписка о лимите один раз перегенерируется.
- Для mini/gpt54/gpt55 натал и прашна локально используют packet=maximum.
- pro/pro2/pro3 по умолчанию model-only, но ключ `локалэфемериды`/`локал`/`расчёт локально` принудительно включает тот же maximum-пакет.
- Локальный пакет передаёт все рассчитанные поля и аудит; критическая неполнота прерывает запрос. `ASTROLOGY_REQUIRE_SWISS_FILES=1` запрещает Moshier fallback.
- Натал всегда развёрнутый; обычная прашна краткая, а `подробно`/`глубокий разбор`/`максимальный техрасчёт` и все pro-режимы дают развёрнутый технический ответ.
- GigaChat только по явному слову «гигачат».
- Явная память изолирована по peer_id; забывание ставит active=0.
- Скрейперы запускаются только вручную: `парсер` показывает каталог, `парсер все` последовательно запускает все источники, `парсер <id>` или `парсер запустить <id>` запускает один.
- Событие сохраняется только при наличии сути, даты и конкретного места.
- Владелец может вручную добавлять события; при ссылке браузер открывает страницу и оставляет вкладку.
- Роль и теплоту может менять любой участник текущего диалога.
- Активное общение — единый master switch: при выключении прекращаются реакция 1/10, фоновые реплики и автоматические перепалки; `next_outburst_at=0`, stale-генерации отменяются перед отправкой.
- Фоновые реплики только при одновременно включённом активном общении и роли быдло/дурачила, через 1–60 минут; сценарии: беседа 40%, в воздух 40%, участник 20%; генерация всегда Luna/Terra 50/50, шаблон только fallback.
- Активное общение отвечает примерно на каждое десятое содержательное сообщение холодно, цинично и грубо; модель случайно Luna/Terra 50/50.
- Telegram owner видит кнопку добавления события; обычные пользователи её не видят.
- В справке ЛС нет команд групповых чатов и упоминаний групповой беседы.
- V107 dedupe работает precision-first: `DIESEL HALL` и `Diesel Bar` — разные площадки; hard venue/time conflicts не переопределяются AI; соседние даты объединяются только при явной многодневности; verified snapshot V3 привязан к `dedupeAlgorithmVersion`.

Перед ответом сначала изучи файлы и покажи, какие конкретно модули будут изменены. После этого реально измени архив, а не только опиши решение.
```

## Что приложить к новому чату

Минимум:

1. полный source archive V107 без секретов и рабочей базы;
2. этот `CHAT_HANDOFF.md`;
3. при проблеме — точный console log и скриншот;
4. при проблеме данных — обезличенный пример строки, не всю базу.

Для продолжения существующих данных новая версия должна накладываться на локальный проект пользователя, где уже лежат `.env` и `data/bot.sqlite`.

## Нерешённые технические долги

- `src/app/botApplication.js` всё ещё около 10 тысяч строк.
- `src/infrastructure/database/index.js` около 4 тысяч строк.
- Нет live integration test environment.
- Точность model-only астрологии зависит от выбранной модели. Локальный maximum зависит от файлов Swiss; аудит явно показывает Moshier fallback и optional-пробелы.
- Длинные Sol-streams иногда падают по capacity/terminated; V47 делает ограниченное восстановление, но внешний router всё равно может остаться недоступным.

## Последняя проверенная функциональность

V65 сохраняет V64 и добавляет три startup-попытки Telegram, диагностику `api.telegram.org`/`t.me`, классификацию сетевых и API-ошибок, автоматическое переподключение каждые пять минут и owner-команду `телеграм проверить`. V64 жёстко перехватывает все команды парсера до GPT, добавляет короткую форму `парсер <id>`, нормальные тексты ошибок и пропуск Telegram-фона при offline-старте. V62 закрывает досье для всех, кроме владельца. V61 добавляет fuzzy-цель и on-demand backfill досье. V60 защищает self-target запросы от ошибочного поиска участника.


## V65: диагностика и автоматическое восстановление Telegram

- startup выполняет до трёх попыток с задержками 2 и 5 секунд;
- `ECONNRESET` до TLS отделяется от 401 неверного токена и 409 конфликта polling;
- при неудаче VK продолжает работу, а Telegram переподключается каждые пять минут;
- owner-команда `Гигорейв телеграм проверить` проверяет Bot API, t.me, getMe и webhook;
- токен в диагностике не публикуется;
- сетевой патч не обходит блокировку VPN/провайдера, а диагностирует и восстанавливает соединение после возвращения сети.
