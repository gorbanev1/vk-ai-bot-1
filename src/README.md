## V107: промышленная precision-first дедупликация афиши

V107 усиливает `тусы проверить`, canonical registry и финальный verified snapshot. Приоритет — не склеить две разные тусы даже ценой того, что сомнительная пара останется раздельной до AI/ручной проверки. `DIESEL HALL` и `Diesel Bar` зафиксированы как разные площадки; голый `DIESEL` считается неоднозначным брендом. Разные площадки или явно несовместимое время на одной дате являются hard-negative и не могут быть отменены AI.

Родовые названия (`концерт`, `вечеринка`, `event`, `live` и т. п.) не считаются identity-якорем. Один совпавший артист из длинного лайнапа больше не означает полный матч. Соседние даты объединяются как многодневник только при явном multi-day evidence. При этом безопасный title-containment сохраняет recall для карточек вида `TATTOOMO 2026` ↔ `TATTOOMO 2026 — тату-фестиваль ...`.

AI используется только для серой зоны и не может переопределить hard conflicts; внешний текст события помечен как недоверенный, чтобы инструкции из постов не влияли на dedupe-задачу. Кластеризация использует complete-link/lineage guard против транзитивного overmerge. Финальный paranoid pass переведён с скрытого O(N²) на candidate blocking: синтетическая проверка 2000 разреженных событий проходит примерно за несколько секунд вместо >2 минут в предыдущем варианте.

Версия verified snapshot повышена до `3` и дополнительно привязана к `dedupeAlgorithmVersion=event-dedupe-v107-industrial-1`, поэтому старый canonical cache автоматически инвалидируется после обновления. Обязательный adversarial suite: `tests/events/eventDedupeIndustrialV107.test.mjs`.

## V95: authoritative date/time + complete-link dedupe

Исправлен критический баг V94: даты из сырого текста больше не собираются в искусственный min/max-диапазон. Однодневное событие не может растянуться до конца месяца из-за чужой даты в соседнем тексте, а `21.08.26` не может стать временем `21:08`. Публичная афиша теперь передаёт в новый dedupe именно сырые карточки источников — legacy merge до второго контура отключён для этого маршрута.

Это блокирует транзитивные гибриды вроде смешивания `TATTOOMO`, `Мото Што-то!` и другого концерта через промежуточную запись. После первого merge запускается дополнительный verification-pass; новая серая зона снова проверяется GPT. Многодневные события сохраняют только реально доказанные дни, время и площадки, а все Telegram/VK источники объединённой карточки сохраняются.

## V94: глубокий dedupe без повторов + AI merge деталей

Афиша сравнивает не только один `eventDate`, а календарные интервалы `displayDate`, поэтому один многодневный ивент из разных источников больше не разъезжается на две карточки. Введён `eventDays[]` и compact-вывод по дням/локациям. Для объединённой карточки показываются все источники. Финальный fixed-point pass запрещает очевидным одинаковым названиям с пересекающимися датами остаться двумя строками.

## NVIDIA V74: увеличенное окно ожидания Visual API

По фактическому логу hosted NVIDIA Visual endpoint вернул собственный HTTP 504 примерно через 302,5 секунды. Клиентский лимит одной модели в 120 секунд мог оборвать запрос раньше ответа NVIDIA, поэтому значения по умолчанию увеличены:


Одна модель теперь получает до 6 минут, а вся автоматическая цепочка — до 20 минут. Это не заставляет NVIDIA считать дольше её серверного лимита: если endpoint сам вернёт 504 раньше, бот сразу перейдёт к следующей модели. `401/403/404/422` также обрабатываются сразу, без ожидания клиентского тайм-аута.

## NVIDIA V73: настоящий fallback после HTTP 504

В V72 запрос к `flux.1-schnell` мог ждать около пяти минут, получить HTTP 504 и завершиться, хотя лог ошибочно писал `FALLBACK`. V73 считает 504 и прочие 5xx временными ошибками endpoint и действительно запускает следующую модель в режиме `auto`.

Таймауты разделены:

```dotenv
NVIDIA_IMAGE_ATTEMPT_TIMEOUT_MS=120000
NVIDIA_IMAGE_TOTAL_TIMEOUT_MS=600000
```

Первый ограничивает одну модель, второй — всю команду. Старый `NVIDIA_IMAGE_TIMEOUT_MS` остаётся совместимым псевдонимом общего бюджета команды. В логе реальный переход виден как `FAILED`, затем `NEXT`, затем новый `START`.

Неизвестные прямые NVIDIA-команды также получают короткую ошибку. Для текстового вызова без ручного выбора модели добавлена форма:

```text
Гигорейв nvidia текст <вопрос>
```

Полная справка остаётся доступна явно: `Гигорейв nvidia помощь`.

## NVIDIA V69: короткие команды без GPT-перехвата

Команды `Гигорейв nvidia`, `Гигорейв нвидиа` и `Гигорейв энвидиа` теперь сразу показывают NVIDIA-справку со всеми командами и готовыми примерами. Они не уходят в обычную `gpt-5.4-mini`.

Полный каталог, видимый ключу, с кратким описанием назначения каждой модели:

```text
Гигорейв nvidia доступные по этому апи ключу модели с описанием возможностей каждой
```

Для коротких NVIDIA-команд промежуточные сообщения о выборе endpoint и каталога скрыты; итоговый ответ остаётся диагностическим и показывает модель/HTTP.

## NVIDIA V68: тест без выбора модели

Главная команда владельца:

```text
Гигорейв api nvidia полный тест
```

Она проверяет ключ, перебирает до 30 chat/instruct-моделей до первой реально доступной аккаунту и запускает пять готовых запросов. `GET /models HTTP 200` подтверждает ключ, но отдельный model id из общего каталога всё равно может вернуть account-specific `HTTP 404`; V68 автоматически пропускает такие модели.

Дополнительные команды:

```text
Гигорейв api nvidia рабочая модель
Гигорейв api nvidia тест авто
Гигорейв api nvidia запрос авто Объясни простыми словами, что такое квантовая запутанность
Гигорейв api nvidia примеры
```

## V67: безопасный выбор NVIDIA-моделей и исправление прашны

- `api nvidia проверить` по-прежнему отдельно подтверждает ключ через `GET /models`.
- Список моделей теперь пронумерован; `#N`, точный model id, уникальная часть имени и `авто` поддерживаются в командах `тест` и `запрос`.
- `organization/model-name`, `<model>` и другие примеры-заглушки отклоняются до сетевого запроса с понятным объяснением.
- Команда `api nvidia примеры` строит готовый набор тестов с реальным model id из текущего каталога.
- Если `GET /models` успешен, а `POST /chat/completions` вернул 404, бот прямо сообщает: ключ работает, проблема относится к модели или совместимости endpoint.
- Явная прашна/натал больше не перехватывается анализом участника беседы. Фразы `локальным софтом`, `локальным движком` и `локальным ПО` принудительно включают максимальный локальный расчёт.

- Прямые диагностические ключи хранятся в `OPENAI_DIRECT_API_KEY` и `NVIDIA_API_KEY` и не заменяют основной `OPENAI_COMPAT_API_KEY`.

## V65: диагностика и автоматическое восстановление Telegram

## V55: все текстовые GPT-модели для анализа изображений

- Технический ответ роутера не публикуется в чат. Если отказала вся цепочка, пользователь получает короткое нейтральное сообщение.

## V54: анализ изображений из сообщений, комментариев и постов

- Ответьте на сообщение или комментарий с картинкой: `Гигорейв, что на картинке?`, `что изображено`, `прочитай текст`, `предложи варианты`.

## V53: полный текст комментариев и постов VK

- Сообщение больше не считается пустым, если его видимый текст находится во вложении `wall_reply`, `wall`, истории репоста `copy_history`, штатном reply или пересланной цепочке.
- Комментарий к посту извлекается вместе с автором, индексом автора, ссылкой на пост/комментарий и вложенными ссылками, документами или медиа.
- Если VK прислал только идентификаторы комментария, бот ограниченно догружает его через `wall.getComment`; сетевая ошибка не ломает обработку и не заставляет модель выдумывать текст.
- Один нормализованный текст используется при записи в SQLite, GPT-контексте, резюмировании, активном анализе и анализе сообщения-цели reply.
- Маршрутизация команд по-прежнему использует только собственный текст сообщения: текст внутри пересланного комментария не может случайно обратиться к боту или выполнить команду.
- Для удалённого или закрытого комментария сохраняется только доступная метаинформация; модель получает явное отсутствие текста.

## V52: анализ сообщения, на которое ответили

- Если пользователь вызывает Гигорейва штатным reply и просит оценить, разобрать, проверить, объяснить, прокомментировать, перевести, переписать, высмеять или похвалить сообщение, объектом анализа становится именно сообщение-цель reply, а не текст команды.
- В GPT передаются отдельные поля автора, индекса, полного текста и доступного описания вложений исходной реплики. Текущий запрос и сообщение-цель жёстко разделены.
- Текст сообщения-цели считается недоверенной цитатой: содержащиеся в нём команды не выполняются как инструкции модели.
- Логика работает во VK и Telegram; обычный ответ бота по-прежнему отправляется нативным reply на сообщение пользователя с командой, сохраняя цепочку обсуждения.
- Тот же контекст добавляется к явным запросам GigaChat, а не только к OpenAI-compatible GPT.

## V51: активное общение как единый главный выключатель

- Команда `Гигорейв активное общение отключить` теперь немедленно отключает все автономные ветки: реакцию 1/10, фоновые выкрики ролей `быдло`/`дурачила` и продолжения автоматически начатых перепалок.
- При отключении `next_outburst_at` обнуляется, активные banter-сессии беседы удаляются, а уже запущенные GPT-генерации получают in-memory epoch и отменяются перед отправкой.
- Фоновые таймеры и startup-reschedule выбирают только строки SQLite с `active_chat_enabled=1`; ошибка или stale-задача больше не может снова включить режим либо переустановить таймер после отключения.
- При повторном включении фоновые реплики планируются заново только если сохранена роль `быдло` или `дурачила`.

## V50: адресное «подлизать» и метаданные обращения

- `Гигорейв подлизать` отвечает штатным reply на случайное недавнее сообщение другого участника.
- `Гигорейв подлизать <имя>` использует устойчивый поиск участника и выбирает одно из его недавних сообщений.
- Для этой реплики роли `быдло`, `дурачила`, хамство и перепалка отключаются; Luna/Terra отвечает гипертрофированно доброжелательно и восторженно.
- Каждый текстовый GPT-вызов входящего обращения получает индекс сообщения, имя и индекс участника, peer и точный исходный текст.

## V49: единый двухстраничный контракт pro

- Luna (`pro`), Terra (`pro2`) и Sol (`pro3`) во VK и Telegram могут выдавать законченный ответ объёмом до двух больших страниц.
- Обычное ограничение «8–10 предложений» для pro не применяется; лимит одного сообщения платформы также не считается лимитом всего ответа.
- Если пользователь просит заведомо больше — например 10 000 слов или восемь страниц — модель не спорит о длине и не предлагает другой формат, а молча выдаёт лучший законченный вариант в пределах двух страниц.
- Короткий мета-ответ вида «не влезает», «могу предложить другой формат» или «разобьём на части» автоматически распознаётся и один раз перегенерируется с исправленным контрактом.
- Общий предел pro выровнен до 14 000 символов и 10 000 `max_completion_tokens`; длинный текст автоматически делится на несколько нативных reply-сообщений.

## Что изменилось в V45

- Автономные ответы режима «активное общение» получили отдельный жёсткий промпт: холодный цинизм, язвительность и грубость, привязанные к реальным словам чата, без мягкой клоунады и сюрреалистической бредятины.
- Все генеративные реплики активного поведения — самостоятельные ответы, фоновые выкрики и продолжение перепалки — случайно используют Luna (`pro`) или Terra (`pro2`) с вероятностью 50/50.
- В ролях `быдло` и `дурачила` фоновые реплики запускаются через случайный интервал от 1 минуты до 1 часа.
- Сценарий фоновой реплики выбирается по фиксированным весам: вся беседа 40%, выкрик в воздух 40%, конкретный участник 20%.
- Сценарий «вся беседа» анализирует недавний транскрипт; сценарий «участник» получает его недавние сообщения. Перепалка открывается только после адресного сценария.
- `быдло` стало приземлённо грубым и холодно-циничным; `дурачила` — правдоподобно тупым, примитивным и самоуверенно неправым, без говорящих холодильников, случайных овощей и сказочного абсурда.
- Старые расписания 1–3 часа при запуске автоматически зажимаются в новое окно 1–60 минут без миграции схемы SQLite.
- Сохранены все исправления V44: VK reply/цитаты и суточное окно для команды `доебаться` / `фас`.


## V48: нативные ответы на конкретное сообщение

- В VK все ответы на входящий запрос отправляются через штатный `MessageContext.reply()`, поэтому клиент показывает их как настоящий ответ на исходное сообщение.
- В Telegram `sendMessage`, `sendPhoto` и `sendDocument` получают `reply_parameters.message_id` входящего сообщения; это работает и внутри форумных тем.
- Команды, GPT, натал, прашна, ошибки, изображения, прожарка и огрызания используют один транспортный контракт.
- Автономные фоновые выкрики остаются обычными сообщениями, потому что у них нет конкретного входящего сообщения.

## V47: задержанный повтор GPT и защита памяти от обзываний

- временная ошибка текстовой модели повторяется той же моделью через случайные 5–30 секунд;
- после второго отказа выбирается следующая доступная модель по уровню mini → 5.4 → 5.5 → Luna → Terra → Sol;
- ошибка не отправляется пользователю, пока ограниченная схема восстановления не исчерпана;
- конструкции «теперь ты лох», «ты залупа, запомни» и «запомни: теперь ты ...» не записываются в память и получают отдельный резкий ответ;
- распознаются варианты обращения «Гигарейф», «Гигорейф», «Гигарейв» и «Гигорэйв».

## V46: локальные эфемериды для pro и аудит полного пакета

Команды натала и прашны понимают `локалэфемериды`, `локал` и `расчёт локально`. Ключ включает локальный `packet=maximum` даже для Luna/Terra/Sol. В модель уходит весь рассчитанный пакет и аудит покрытия; критическое отсутствие обязательного расчёта завершает запрос ошибкой, а optional-пробелы перечисляются явно. `ASTROLOGY_REQUIRE_SWISS_FILES=1` запрещает fallback на Moshier. Для натала используется часовой пояс места рождения.

Важно: maximum означает всё, что реально реализовано вычислителем, без усечения для LLM. Проект не выдаёт математические D1–D60 за полную реализацию всех традиционных варг, Shadbala, Ashtakavarga и всех йог.

## V57: вопросы про участников по данным беседы

Обычный вопрос вида `Гигорейв почему Тимосин всё время хочет пиздеться?` сначала локально сопоставляется с участниками текущей беседы. Поиск учитывает настоящее имя, сохранённое имя/ник, транслитерацию, опечатки, Jaro-Winkler, Levenshtein и общий префикс. Выбирается максимальное совпадение; например, `Тимосин` может быть сопоставлен с `Тимофей`.

После выбора бот анализирует все сохранённые сообщения этого участника в текущей беседе, разбивая большую историю на блоки. В окончательный GPT-запрос передаются настоящее имя, исходный вопрос и извлечённые материалы. Бот не выдаёт скрытые мотивы или диагнозы за факты: при недостатке данных он обязан обозначить неопределённость.

## V58: учитываются сообщения других людей об участнике

После fuzzy-сопоставления имени бот ищет не только все сообщения самого найденного участника, но и все сообщения других людей, где он упоминался. Поиск использует форму из текущего вопроса (`Тимосин`), настоящее имя (`Тимофей Тимофеев`), отдельные части имени, ники, username, VK mention и похожие словоформы.

В GPT передаются два раздельных блока: собственные сообщения участника и сообщения других людей о нём. Первый блок считается основным источником наблюдений, второй — контекстом восприятия, шуток, конфликтов и чужих оценок. Чужие слова не превращаются автоматически в факты.

## V59: исправление падения обычных GPT-команд

В V58 функция `parseImageEditRequest()` вызывалась оркестратором, но её import был потерян при объединении патчей. Из-за этого анализ изображений мог работать по раннему маршруту, а обычные GPT-команды падали с `ReferenceError: parseImageEditRequest is not defined`. V59 восстанавливает import и добавляет регрессионный тест на саму интеграцию.

Telegram остаётся необязательной платформой: ошибка TLS/`ECONNRESET` при его старте теперь логируется как деградация, но не блокирует запуск VK Long Poll. Для повторного подключения Telegram после восстановления сети требуется перезапуск процесса.

## V60: защита маршрута вопросов про участников

Вопросы про самого бота (`у тебя`, `ты`, `твой`, `свои сообщения`) больше не запускают поиск человека по базе. Нормализация stop-words исправлена: служебные слова вроде `все`, `свои` и `сообщения` не могут ошибочно сопоставляться с именем участника. Минимальный fuzzy-порог повышен до 0.84, при этом намеренное сопоставление вроде `Тимосин` → `Тимофей` остаётся рабочим.

## V61: fuzzy-поиск участника для скрытого досье

Скрытая команда `досье` теперь принимает не только точный `@username`, но и обычное имя, ник или похожую форму. Например, `Гигорейв досье тимасин` локально сравнивается с участниками текущей беседы и выбирает максимальное совпадение по тем же alias, транслитерации и fuzzy-метрикам, что используются в вопросах про участников. Для VK в alias дополнительно загружается `screen_name`.

После правильного определения участника досье читается строго по его числовому `user_id`. Если сохранённых фактов ещё нет, после успешного пароля бот один раз строит досье по всем собственным сообщениям этого участника в текущей беседе, сохраняет результат в SQLite и затем выводит его. Чужие сообщения и упоминания не записываются как факты досье.

## V62: досье только для владельца

Скрытая команда `досье` теперь полностью закрыта для обычных участников. Проверка владельца выполняется до fuzzy-поиска цели, запроса пароля, чтения сообщений и построения фактов. Для VK владельцем считается служебный owner ID проекта; для Telegram — пользователь из `TELEGRAM_OWNER_USER_ID`. Посторонний получает только `Команда недоступна.`

Старое ожидание пароля также не даёт обойти ограничение: при сообщении от постороннего pending-авторизация удаляется, а `beginDossierAuthorization` и `finishDossierAuthorization` повторно проверяют владельца.


## V63: подсказка парсера и запуск всех источников

Команда `Гигорейв парсер` больше не уходит в обычный GPT-ответ: владелец получает локальный список всех включённых источников с точными идентификаторами `tg:...`, `vk:...` и `chat:...`, а также примеры команд.

Команда `Гигорейв парсер все` последовательно запускает все настроенные источники. Публичные Telegram/VK-источники выполняют принудительный проход, а для каждой настроенной VK-беседы открывается ручная сессия. В конце бот показывает число успешных и неудачных запусков и результат по каждому источнику. Команда остаётся доступной только владельцу.

## V64: жёсткая маршрутизация команд парсера

Команды `Гигорейв парсер`, `Гигорейв парсер <source-id>` и `Гигорейв парсер все` теперь проверяются до GigaChat, анализа изображений, поиска неизвестных терминов и обычного GPT. Поэтому они не могут превратиться в ответ модели «уточните, что сделать с парсером».

Короткая форма запуска одного источника: `Гигорейв парсер tg:kurazhcity`. Форма `Гигорейв парсер запустить tg:kurazhcity` сохранена. Ошибки источников выводятся текстом вместо `[object Object]`; полная техническая диагностика остаётся в консоли. Если Telegram Bot API не подключился при старте, фоновые Telegram-реплики пропускаются до следующего запуска процесса и не тратят GPT-запросы.


## V79 — Telegram: прашна отключена

- Явный запрос прашны в Telegram не запускает астрологический обработчик и получает короткое уведомление, что команда доступна только в VK.
- Натал в Telegram остаётся доступен.
- VK-прашна не изменена.
