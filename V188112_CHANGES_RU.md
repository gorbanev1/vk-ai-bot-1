# V188.112 — журнал SSE и восстановление того же responseId

Версия собрана поверх V188.111, основной SINGLE-SHOT /files → input_file.file_id,
4-часовая отправка Telegram, 1000 временных ошибок background polling и outbox сохранены.

## Что изменилось

- `consumeOpenAIStream()` вызывает `onActivity` при **любых полученных байтах**,
  в том числе фрагменте ещё не завершённого JSON и SSE heartbeat `: ping`.
  Это было реализовано до V188.112 и подтверждено поведенческим тестом.
- Добавлены async `onChunk` и `onDone` (контрольный `[DONE]`, не текст модели).
- Только для дорогого project-audit SSE каждый реально полученный chunk сохраняется
  в приватный `data/audit-jobs/<jobId>/stream/<attempt>.sse`, текстовые deltas —
  отдельно в `<attempt>.partial-answer.txt`, типы событий — в `.events.ndjson`,
  короткое состояние/responseId — в `.progress.json`. Директории 0700, файлы 0600.
  Размер сырого журнала ограничен 512 МиБ, переполнение помечается, но само
  inference не обрывается. Ошибка журнала не превращает ответ модели в новый POST.
- `response.created` / `response.in_progress` / `response.completed` дают
  `responseId` из события. Его немедленно записывают в журнал и основной
  checkpoint; ошибка callback несёт известный ID и не допускает второй POST.
  После рестарта single-shot recovery ищет потерянный `responseId` также в
  локальных .progress.json. При неоднозначных нескольких ID он не выбирает один
  наугад.
- SSE project-audit допускает успех только при явном `response.completed`
  (с объектом response) или финальном `[DONE]`. Обычный EOF с накопленным
  текстом — **не готовый результат**, а `PROJECT_AUDIT_STREAM_INCOMPLETE`.
- При обрыве stream **с известным ID** выполняется polling/GET того же ID, без
  нового inference. Для этого в проектном SSE запросе `store:true` (если router
  поддерживает сохранение/GET). Если router не поддерживает retrieval — остаются
  источник, журнал, checkpoint и состояние для ручной проверки, без ложного
  обещания «продолжить с любого байта».
- Если уже пришли **какие-либо байты stream**, локальный ambiguous re-POST
  теперь запрещён: накопленный частичный текст не позволяет угадать прогресс
  обработки архива. Два разрешённых ранее ambiguous re-POST могут по-прежнему
  применяться только к обрыву POST **до первого байта и без responseId**:
  это осознанная success-first политика предыдущей версии и потенциальный
  двойной inference, если router игнорирует Idempotency-Key.
- Уведомление при известном ID теперь не говорит, что сама модель «остановлена»:
  прерван транспорт, а предыдущая сессия может ещё работать.

## Настройка idle

Текущий default `OPENAI_STREAM_IDLE_TIMEOUT_SECONDS=14400` (4 часа) **не
уменьшен** без отдельного решения пользователя: он ранее просил не убивать
долго размышляющую модель, которая временно не присылает байты. Если конкретный
router гарантирует heartbeat чаще двух минут, можно явно указать
`OPENAI_STREAM_IDLE_TIMEOUT_SECONDS=120`. Это **таймер отсутствия байтов**, а
не абсолютный лимит длительности stream. Общий project-audit ceiling по-прежнему
24 часа; его не нужно путать с коротким сетевым idle timeout.

## Что НЕ обещается

- Partial-answer.txt — только диагностика, не проверенная часть аудита и не ZIP.
- GET существующего stream response не гарантируется сторонним router.
  Код пробует GET того же ID, но не выдумывает resume endpoint.
- Если router не прислал ID и не умеет lookup по idempotency key, продолжить
  старый inference нельзя гарантированно; в варианте без байтов остаётся
  ограниченная previous success-first retry-политика.
- Полноценное автоматическое восстановление *каждого отдельного MULTIPASS stage*
  здесь не добавлено; для него требуется отдельный stage-journal и работа со
  state machine каждого batch. MULTIPASS остаётся опциональным.
- Поведенческие тесты проверяют SSE heartbeat, фрагменты событий, запись
  журнала и [DONE]; тест полного workflow с реальным router и crash-restart
  не проводился. После запуска на проде стоит проверить его на дешёвом job.
