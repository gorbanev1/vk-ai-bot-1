# GIGORAVE — проект V188.143 / восстановление афиш и полный явный Vision-аудит

Основа: STAGE6 с защитой verified snapshot и исправлением восстановления posterImageIndex, а также с командой удаления источников владельца. В этой поставке не заменена архитектура захвата VK/Telegram, parser admission, исходных слоёв, событий, ledger, дедупликации или планировщика Astra. Полная трассировка Astra, отсутствие нового watchdog/таймаута на её текстовые задачи и защита от повторной оплаты не изменялись.

## Обнаруженная причина отсутствующих фото

Часть старых событий имела сохранённые image_paths_json и poster_vision_facts_json, но poster_image_index=0. Строгая выдача отвергала их до оценки уже существовавшего доказательства. Узкая проверка восстановит индекс без записи в БД только при однозначном подтверждении даты, идентичности события и конкретного пути картинки. Неподтверждённые и неоднозначные фото по-прежнему не подставляются в карточку автоматически.

## Полная повторная проверка старых изображений — команда владельца

В личном Telegram-чате владельца:

    тусы картинки полная проверка

Это отдельный ЯВНЫЙ платный проход. В отличие от старой команды «тусы метаданные картинок заполнить», он пытается заново вызвать Vision для КАЖДОГО сохранённого локального изображения источников VK Public, VK Chat, Telegram и ручных событий, включая исходные записи БЕЗ готового Event. Искусственного лимита в 12 картинок для аудита нет. Перед запуском следует оценить количество изображений и стоимость; команды не запускаются автоматически после старта бота или обычного «парсер все».

Результаты создаются на рабочей машине в отдельном каталоге:

    data/event-image-review/<дата-время>/
        all-image-ratings.csv
        all-image-ratings.json
        images/<контрольная-сумма>.<расширение>

Каждая строка CSV/JSON содержит тип источника и его ключ, eventId, название и дату при наличии, номер изображения, путь оригинала, путь отдельной копии для проверки, результат Vision или причину его отсутствия, тип картинки, уверенность модели, оценку совместимости с конкретным Event, причину принятия/отказа и извлечённые текстовые признаки. Ошибка Vision, отсутствующий локальный файл и raw-запись без Event явно различаются. Исходные картинки НЕ удаляются. При ошибке отдельной картинки старая привязка события НЕ признаётся проверенной автоматически.

Если исходное изображение осталось только удалённым URL либо файл из `data/` недоступен, Vision не может честно проверить его без восстановления файла: строка отчёта помечается `source-image-not-downloaded` или `vision-retry-required`. Исходный архив проекта не содержит пользовательских изображений или рабочей БД, поэтому при тестировании нельзя забыть перенести прежнюю папку `data/` в рабочую установку. Архив профиля Chromium не заменяет `data/` с сохранёнными фотографиями.

Результаты Vision для исходной записи без итогового Event сами НЕ создают мероприятие: нужен отдельный штатный повторный разбор этой записи с доказанной датой. Для старых исходных ссылок существует отдельная команда «тусы перепарсить по ссылкам»; она может запускать дополнительные платные запросы. Повторное получение файлов, которых уже нет по исходной ссылке, невозможно гарантировать.

## Подтверждение владельцем

После явного аудита спорные существующие Event с локально доступными кандидатами предлагаются владельцу в Telegram с прикреплёнными фотографиями и вопросом «Это изображение относится к этому анонсу?». Ответ номером (или «да» при одном кандидате) сохраняет точно выбранный файл и конкретный eventId/дату/название. Ответ «нет» сохраняет отказ без удаления исходных медиа. «Отмена» не принимает решение. Повторный автоматический backfill не перезаписывает это подтверждение, а смена даты/названия/изображения отменяет применимость старого подтверждения к новой карточке. Пары после подтверждённой дедупликации сохраняют привязку с provenance, а не выбирают чужую картинку по одному сходству.

Если Telegram был недоступен или есть ещё вопросы, использовать:

    тусы картинки на ревью

Для пересборки актуальной афиши после успешного прохода:

    тусы проверить

Запрос «тусы эти выходные» сам по себе не запускает Vision: он читает уже собранный verified snapshot. Обычный `парсер все` не гарантирует повторный Vision для уже финальных ledger-строк и не чинит пропавшие локальные файлы.

## Логи и приватные данные

Поставка не содержит старых `data/logs`, логов Astra, браузерного профиля, SQLite, SQLite-WAL/SHM, `.env`, секретов и `node_modules`. Текущие журналы и диагностику платных запросов на твоём компьютере НЕ удаляли: у среды сборки нет доступа к реальной папке логов. Служебные SSE/http-трассы Astra нужны для диагностики и предотвращения повторной оплаты; их нельзя без разбора считать «нерелевантными». Новый CSV/JSON/фото-отчёт хранится в `data/event-image-review/`, отдельно от старых логов. Присланный browser-profile содержит потенциально приватные cookies/авторизацию и в архив не входит.

## Проверки и границы

`node scripts/check-syntax.mjs`, `node scripts/check-imports.mjs`, `node scripts/check-named-imports.mjs` и целевые офлайн-тесты — см. протокол в ответе с архивами. На присланной копии реальной SQLite и с реальным платным Vision здесь НИЧЕГО не переписывалось и НЕ запускалось. Команда с платным Vision должна выполняться владельцем на его авторизованной установке с полной папкой локальных изображений. Полный end-to-end VK/Telegram/AI остаётся предметом проверки после установки; гарантировать отсутствие любых дефектов по одним офлайн-тестам нельзя.

Перед обновлением сохранить копию всей рабочей папки, `.env`, `data/`, SQLite и соответствующих WAL/SHM согласованным способом. Не распаковывать проект поверх работающей SQLite и не удалять data/ ради «чистой» установки.
