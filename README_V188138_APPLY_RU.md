# Gigorave V188.138 — эталонные DOM-слепки VK из реальных браузерных вкладок

## Что изменено

Этот накопительный ZIP содержит код предыдущей V188.137 и дополнительный **capture-only** механизм. Для **ручных запусков** `vkPublicScraper` и конечного прохода `vkChatEventScraper` перед извлечением текста/анонсов выполняется один `page.evaluate`, внутри которого **в тот же момент** читаются `document.documentElement.outerHTML`, URL, baseURI, doctype, положение прокрутки, viewport и runtime-данные медиа. Полученный HTML сначала записывается на диск, а в точном контуре разбору передаётся **та же строка**, а не повторный снимок уже изменившейся вкладки.

Публичный VK-скрейпер создаёт fixture **на каждой итерации своей существующей прокрутки**, даже если `snapshotEveryScroll=false`; VK-чат сохраняет каждое окно конечного прохода, нижний проход по непрочитанному и финальный снимок. Новый модуль не делает дополнительной прокрутки, не нажимает «Показать ещё», не изменяет VK DOM, не скачивает картинки и не вызывает AI. Поведение отбора афиш и логика сохранения БД не изменены. Существующий V188.137 журнал афиш сохраняется отдельно.

## Где находятся слепки

После **нового ручного парсинга**, а не прямо после распаковки, смотри:

```text
data/parser-forensic-archives/<runId>/
  trace.jsonl
  vk-dom-fixtures/
    <source-slug>-<source-hash>/
      manifest.json
      iterations/
        000001/
          dom.html
          dom-meta.json
          dom-state.json
          resources.json
        000002/
          dom.html
          dom-meta.json
          dom-state.json
        ...
```

`dom.html` — **только** исходная строка `document.documentElement.outerHTML`; ни очищенного текста, ни результата парсинга туда не добавляется. `doctype` сохранён в метаданных. SHA-256 и точное число UTF-8 байт указаны в `dom-meta.json` и `manifest.json`; `pageUrl`, `baseUri`, `title`, `scrollY`, viewport, язык, направление и runtime-свойства — в `dom-meta.json`/`dom-state.json`. `resources.json` хранит `href`, `src`, `srcset`, `data-src`, `currentSrc`, размеры изображений и computed CSS `background-image`, с индексом исходного DOM-элемента. Для открытых shadow root и доступных same-origin iframe сохраняется отдельный HTML; недоступные cross-origin iframe нельзя получить через страницу. `trace.jsonl` содержит событие `vk.fixture.persisted` с файлом, SHA-256 и номером итерации либо `vk.fixture.failed` с ошибкой.

DOM-итерации — отдельные оригинальные файлы; `manifest.json` **обновляется** с добавлением каждой успешно сохранённой итерации. Он не доказывает, что VK загрузил *всю историю* источника: это последовательность состояний, реально увиденных текущим скрейпером. Если VK удалил пост до первого снимка, этот механизм не восстановит его задним числом. Снимки chat live-потока, собранные вне конечного ручного прохода, этим изменением не охвачены.

Отдельный контрольный `expected/announcements.json` **не создаётся автоматически**: ожидаемые анонсы нужно разметить по настоящему сохранённому baseline вручную/после независимой проверки; копировать туда вывод старого парсера в качестве эталона нельзя. Контуры 2/3 (изменённые DOM) и новый полностью офлайн `vkAnnouncementParser` **не реализованы в этой версии**. Сначала нужен реальный fixture; нынешняя команда офлайн умеет проверять его полноту и идентичность, но не извлекать анонсы. Код `vkPublicScraper`/`vkChatEventScraper` пока продолжает часть эвристического и media-извлечения из живой VK-вкладки; это не объявлено офлайн-разбором.

## Проверка без VK, браузера и сети

Из корня проекта (путь к конкретному source-каталогу взять из `vk.fixture.persisted`):

```bash
node scripts/vk-dom-fixture-verify.mjs "data/parser-forensic-archives/<runId>/vk-dom-fixtures/<source-slug>-<source-hash>"
```

Утилита проверяет каждый `dom.html` по SHA-256 и длине в байтах, соответствие `dom-meta.json`/`resources.json` и отдаёт JSON с перечнем итераций. Повторный запуск с неизменными файлами возвращает тот же JSON. Ошибка проверки свидетельствует о повреждении или неполном fixture, а не о плохом распознавании анонсов.

## Установка и безопасность

Дождись окончания задач, отдельно сохрани проект, `data/`, БД/WAL/SHM и `.env`; останови бот, затем распакуй ZIP **в корень текущего проекта** с заменой кодовых файлов. Архив не содержит рабочую `data/`, реальные DOM-снимки, БД, токены и картинки. Не запускай два экземпляра бота и не удаляй старые афиши. После установки проверь `npm run test:v188138`, запусти **один штатный ручной парсинг** и сохрани папку `vk-dom-fixtures` целиком.

**Не пересылай raw DOM/`dom-state.json` публично без проверки**: они могут содержать личные сообщения, ссылки, данные страницы, значения форм и секреты VK. HTML и state намеренно не редактируются ради воспроизводимости; доступ к каталогам ограничить. Создание большого числа HTML-снимков увеличит расход диска и время парсинга. При ошибке нового capture ручной проход может прерваться вместо незаметного продолжения без слепка.
