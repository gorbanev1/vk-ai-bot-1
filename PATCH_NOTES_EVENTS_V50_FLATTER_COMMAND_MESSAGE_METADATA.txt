EVENTS V50 — FLATTER COMMAND + MESSAGE METADATA

Сборка: events-v50-flatter-command-message-metadata

1. Команда «подлизать»
- `Гигорейв подлизать` выбирает случайное недавнее содержательное сообщение другого участника.
- `Гигорейв подлизать <имя>` находит участника по ID, mention, имени, нику, транслиту и fuzzy-совпадению; при необходимости используется GPT-ранжирование.
- Ответ отправляется нативным reply именно на выбранное сообщение из SQLite.
- Для ответа полностью отключаются роли «быдло», «дурачила», хамство, цинизм и активная перепалка.
- Luna/Terra случайно формирует гипертрофированно доброжелательную, лояльную и восторженную реакцию на реальный текст участника.

2. Явный reply на сохранённое сообщение
- VK: исходный `send()` получает `reply_to=<conversation_message_id>`.
- Telegram: `reply_parameters.message_id` получает сохранённый `message_id`.
- Обычные ответы по-прежнему автоматически привязываются к текущему входящему сообщению.

3. Метаданные каждого обращения в GPT
- Обработка входящего VK/Telegram-сообщения выполняется внутри `AsyncLocalStorage`.
- Каждый текстовый GPT-запрос в этой цепочке получает platform, peer_index, message_index, participant_name, participant_index и точный message_text.
- Данные помечены как недоверенные и не могут подменять system prompt.
- Повтор запроса и переход на следующую модель сохраняют тот же блок без дублирования.

4. Проверки
- чистые тесты разбора команды, выбора сообщения, промпта и fallback;
- тест блока входящего сообщения и централизованного подключения;
- транспортные тесты явного reply к старому сообщению для VK и Telegram;
- полная `npm run verify`.
