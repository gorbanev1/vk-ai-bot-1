EVENTS V42 — ГЛУБОКИЕ PRO-ОТВЕТЫ И СКРЫТЫЙ FULL-ПАКЕТ
=========================================================

1. Исправлен порядок профилей длины
-----------------------------------
Раньше ветка prashna выбиралась раньше pro, поэтому даже `pro3 прашна ...`
получала профиль 2–3 абзаца. Теперь:

- обычная прашна без ключа подробности остаётся краткой;
- `прашна подробно`, `глубокий разбор`, `максимальный техрасчёт` получают
  развёрнутый технический профиль;
- `pro/pro2/pro3` прашна всегда получает максимально развёрнутый профиль.

2. Pro-модели работают в глубоком режиме
-----------------------------------------
Для любой текстовой операции, использующей настроенную pro/Luna, pro2/Terra
или pro3/Sol модель, OpenAI-совместимому API передаются:

- reasoning_effort: high
- verbosity: high

Если router отвечает 400/422 из-за неподдерживаемых параметров, бот повторяет
тот же запрос без них. В prompt добавлены требования сначала перепроверить
допущения и расчёты, а затем дать итог без раскрытия скрытой цепочки рассуждений.

3. Локальный full-пакет больше не засоряет чат
----------------------------------------------
Для mini/gpt54/gpt55 прашна и натал по-прежнему рассчитываются локально
максимальным пакетом full. Но пользователь больше не получает отдельные
сообщения с координатами, лагной, положениями, движком и SHA-хешем.

Полный пакет:

- передаётся выбранной модели внутри запроса;
- остаётся в серверных логах;
- не выводится в заголовке готового ответа.

4. Усилен prompt подробной прашны
---------------------------------
В подробном режиме модель должна разобрать технический каркас D1/Whole Sign,
лагну и лагнеша, Луну и накшатру, релевантные дома и управителей, караки,
достоинства, ретроградность/сожжение, аспекты, узлы, панчангу и только полезные
варги/временные методы. После расчётной части требуется связная интерпретация
и прямой итог с указанием степени уверенности.

5. Тесты
--------
Добавлены проверки профилей prashna-detailed/prashna-pro и отдельный модуль
proInferencePolicy, а также статическая проверка отсутствия технических preview-сообщений. Реальные VK, Telegram и router.cheap API в локальных тестах
не вызываются.
