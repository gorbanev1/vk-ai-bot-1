# Gigorave V188.65 — `парсер все чисто`

Добавлен отдельный инкрементальный режим **`парсер все чисто`** для быстрого поиска только новых сообщений/постов без повторной траты алгоритма, poster vision и main AI на уже виденный сырой материал.

## Как работает

- SQLite теперь содержит `manual_parser_seen_items` — независимый raw-ledger **всех** увиденных source-items, включая мусор и записи, которые не стали событиями.
- Ключ дедупликации: `source_id + item_id`. Для каждого item сохраняются источник/URL, время публикации или сообщения, полный сырой текст, вложения, content-hash, first/last seen и статус.
- При первом обновлении ledger автоматически backfill-ится из существующих `telegram_source_posts`, `vk_source_posts` и `vk_chat_source_messages`, поэтому уже известные записи не нужно прогонять заново.
- В `парсер все чисто` запись сначала проверяется по ledger. Если такой source+item id уже существует, она получает `clean-mode-database-known` и **не проходит локальный event-gate, poster vision или main AI**.
- Новые items записываются в ledger сразу после raw capture, ещё до AI.
- Для VK-бесед в чистом режиме отключён history-backfill старых сообщений; читается свежая пачка, а известные CMID отсекаются ledger-ом.
- Для публичных VK/Telegram чистый режим использует обычный incremental capture (`forceInitial=false`) и не запускает media-refresh известных карточек.
- Maintenance-проход восстановления старых афиш в чистом режиме пропускается. Для ремонта/полного перепарса остаётся обычный `парсер все`.

## Команды

- `парсер все чисто` — только новые сообщения/посты.
- `парсер все` — полный проход, перепроверка/ремонт по действующей политике.

В сообщении после capture теперь отдельно показываются `уже видено в raw-ledger` и `новых source-items`.
