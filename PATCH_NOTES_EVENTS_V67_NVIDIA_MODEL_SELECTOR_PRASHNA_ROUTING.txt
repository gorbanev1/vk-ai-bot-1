V67 — NVIDIA Model Selector + Prashna Routing Guard

Причина NVIDIA HTTP 404
-----------------------
Ключ был рабочим: команда GET /models вернула HTTP 200 и каталог моделей. Ошибка возникла потому, что в POST /chat/completions был дословно передан пример «organization/model-name», который не является настоящим model id.

Изменения NVIDIA
----------------
1. Перед каждым test/ask выполняется GET /models.
2. Выбранная модель должна присутствовать в каталоге.
3. Поддерживаются:
   - точный model id;
   - номер #N из пронумерованного списка;
   - уникальная часть model id;
   - селектор «авто».
4. Неоднозначный фильтр показывает совпадения и требует точного выбора.
5. Примеры-заглушки отклоняются локально до POST.
6. «api nvidia примеры» использует реальный model id из текущего каталога.
7. При успешном каталоге и HTTP 404 от chat/completions диагностика отделяет рабочий ключ от ошибки модели/endpoint.
8. Ошибки сохраняют HTTP status для точной классификации.

Изменения прашны
----------------
1. У явной прашны/натала приоритет выше participant database routing.
2. Анализ участника выполняется только при astrologyKind=none.
3. «локальным софтом», «локальным движком», «локальным ПО» распознаются как явный локальный расчёт.
4. Для pro/pro2/pro3 такой ключ принудительно включает maximum local ephemeris packet.

Регрессионные тесты
-------------------
- placeholder model rejection;
- exact/#N/unique/auto selector;
- ambiguous selector error;
- auto chat model preference over embeddings;
- generated NVIDIA examples contain a real id;
- local software wording recognition;
- participant route gated by astrologyKind=none;
- NVIDIA key redaction.
