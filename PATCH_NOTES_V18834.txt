Gigorave V188.34
================
Build: events-v18834-cached-dom-background-processing (0.188.34)

VK DOM-first capture
- VK Public: capture one immutable full page HTML snapshot, write that exact string to diagnostics, run parseVkPublicHtml on it first, then supplement with rendered adaptive/heuristic extraction.
- VK Messenger: because VirtualScroll recycles nodes, save and exact-parse every complete DOM window during history backfill, plus a final capture-complete snapshot. Exact CMID comes from data-itemkey.
- Raw cache is durable before AI processing crosses the processing gate.

Parser-all lifecycle
- COLLECT/CACHE -> owner notification -> PROCESS algorithm+AI -> DONE notification.
- Browser close does not trigger processing and does not block it after cache.
- 10 minutes is a soft status boundary; it does not cancel source processing, AI jobs or final verification.
- Pending status lists only suspected announcement candidates: source + first ~30 characters.

AI processing
- Shared concurrency limiter prevents a request storm across sources.
- Retry-until-settled background pool keeps retryable event jobs alive after the soft boundary.
- Event parsing calls use bounded per-request timeouts.
- Existing configured model ladder is preserved; two technical failures are allowed before escalation to the next available rung.

Diagnostics
- trace.jsonl records capture, cache, processing, retries, soft-boundary and finalization.
- Full .dom.html snapshots are retained in runtime diagnostics for postmortem replay.
- Clean release archive intentionally contains no runtime data/logs/DOM, databases, .env or JSONL files.
