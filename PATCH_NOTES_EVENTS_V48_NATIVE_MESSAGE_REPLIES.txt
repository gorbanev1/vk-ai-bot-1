EVENTS V48 — NATIVE MESSAGE REPLIES FOR VK AND TELEGRAM

Сборка: events-v48-native-message-replies
База: полный V47
Миграция SQLite: не требуется

1. Ответ привязан к конкретному входящему сообщению

Любой пользовательский запрос, который дошёл до обработчика бота, теперь
получает нативный reply платформы, а не отдельное сообщение в общий поток.
Это относится к обычным GPT-ответам, командам, справке, ошибкам, картинкам,
прашне, наталу, прожарке, огрызанию и продолжению активной перепалки.

2. VK

Входящий MessageContext оборачивается прокси-контекстом. Его метод send()
маршрутизируется в штатный vk-io MessageContext.reply(). Сам объект контекста
не мутируется: это важно, потому что reply() внутри SDK может использовать
оригинальный send(), и грубая подмена метода создала бы рекурсию.

Фоновые автономные выкрики не имеют исходного сообщения и по-прежнему
отправляются обычным сообщением.

3. Telegram

Для sendMessage, sendPhoto и sendDocument добавляется официальный параметр:

reply_parameters: { message_id: <id входящего сообщения> }

Параметр работает одновременно с message_thread_id для форумных тем.
Ответы меню в личном Telegram-диалоге также привязаны к нажатому сообщению.
Фоновые уведомления без входящего сообщения отправляются без reply_parameters.

4. Длинные ответы и вложения

Каждая часть ответа, которую пришлось разделить по лимиту платформы, сохраняет
связь с исходным сообщением. Картинка или документ также отправляются нативным
reply, включая подпись и последующий текст, если он не помещается в caption.

5. Проверки

Добавлен тест messageReplyTransport:
- VK context.send вызывает context.reply, а не обычный send;
- прокси не мутирует исходный MessageContext и не создаёт рекурсию;
- Telegram-контекст передаёт message_id входящего сообщения всем типам ответа;
- реальный JSON sendMessage содержит reply_parameters;
- multipart sendPhoto содержит сериализованный reply_parameters.

Реальные сообщения в VK и Telegram с пользовательскими токенами в сборочной
среде не отправлялись. После установки нужен короткий smoke-test в тестовой
беседе обеих платформ.
