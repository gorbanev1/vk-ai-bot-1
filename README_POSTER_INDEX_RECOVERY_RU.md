# GIGORAVE — точечное восстановление подтверждённых афиш

Основа: актуальная STAGE6 со штатной командой удаления источников и остальными предыдущими исправлениями.

## Что было обнаружено

В read-only копии БД, переданной для аудита 21 сентября 2026 года, 32 сохранённых Event имели
`poster_image_index=0` одновременно с доверенным `poster_match_status`, непустым `image_paths_json`
и `poster_vision_facts_json`. Прежний безопасный рендерер отклонял их до проверки реального факта
как `missing-selected-poster-index`. Из 32 строк 23 допускают однозначное восстановление индекса
по уже сохранённому строго совместимому Vision-факту и конкретному пути файла (9 остаются без фото).
Эти числа характеризуют только переданную копию БД, а не состояние работающей установки.

## Исправление

- `src/features/events/eventProvenance.js`: только для `verified_single_event_source_media` и
  `exact_poster_match` при нулевом индексе восстановить индекс, если у события ровно один
  прикреплённый путь, ровно один явный Vision-факт соответствует именно этому пути и строго
  подтверждает дату и идентичность события. Результат не меняет БД самопроизвольно.
- `src/features/events/eventDuplicateResolution.js`: переносить восстановленный индекс вместе
  с подтверждённой афишей при дедупликации. Не переносить незаполненный индекс 0.
- `tests/events/eventPosterMissingIndexRecovery.test.mjs`: тесты однозначного восстановления,
  отказов при чужой картинке, другой дате, неполных фактах, неоднозначности и отрицательных статусах.

## Что НЕ изменено

Не менялись: стратегия capture/admission/processing VK/Telegram, Vision-очередь, правила
формирования событий, модель кандидатов, SQLite-схема, алгоритм сопоставления афиш,
неразрушающая дедупликация, snapshot, ASTRA/AI и её бессрочное ожидание и трассировка.
Нельзя ставить неподтверждённую афишу только ради заполнения карточки.

## Важное для реального запуска

Этот исходный архив не содержит `data/`, рабочих SQLite и `.env`. Обязательно сохраните
эти файлы и каталог со старыми локальными изображениями при обновлении исходников.
Если `imagePaths` в БД указывает на отсутствующий в `data/` файл, восстановление индекса не
создаст изображение. Исторический snapshot мог быть собран до исправления; если выдача всё ещё
использует старую карточку, нужна её штатная пересборка командой владельца `тусы проверить`
(она может вызвать платные AI-запросы). Делайте это только осознанно, при доступном AI.

Входящий `scraper-browser-profile` является профилем авторизованного браузера, не архивом
исходных афиш; он намеренно не включён в готовый проект и не должен пересылаться аудиторам.
