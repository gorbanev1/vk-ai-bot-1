# V188.114 — совместимость `/files` со сторонним router (полный проект)

## Фактическая причина по журналу

V188.113 уже приняла входящий ZIP, сохранила его в source/, проверила 41 entry и собрала sanitized ZIP. Следующий запрос `POST /files` получил HTTP 400 с текстом `Model name not specified, model name cannot be empty`. Ответ не содержит ID загруженного файла, и в представленном журнале нет `astra-running`/`responseId`: подтверждения старта платного inference нет.

## Изменения

- `src/app/botApplication.js`: в `uploadOpenAIInputFile()` передаётся уже выбранное имя модели в отдельном поле multipart `model` **до `/files`**, вместе с `purpose=user_data` и `file`. Для текущего router включено по умолчанию, например `model=gpt-6-astra`. При пустой модели функция завершается локальной ошибкой до отправки запроса.
- `generateOpenAITextWithFilesAttempt()` передаёт в upload ту же модель, которая выбрана для последующего `/responses`. Перед вызовом Astra не возникает отдельного платного вызова модели ради выяснения её имени.
- Совместимость: `OPENAI_INPUT_FILE_UPLOAD_INCLUDE_MODEL=0` отключает дополнительное поле для стандартного Files API, если он его не принимает. По умолчанию `1`.
- Ошибки HTTP 400 не ретраятся автоматически; временные 429/5xx и сетевые ошибки по-прежнему обрабатываются существующей политикой upload. Multipart собирается заново на каждую попытку.
- `projectAuditStage()` печатает текст ошибочного объекта, а не `error=[object Object]`.
- Добавлены поведенческие тесты `tests/ai/v188114RouterFileUploadModel.test.mjs`: тело multipart и один запрос, пустая модель, HTTP 400 без повтора, режим совместимости, вызов upload из Responses, диагностическая строка.

## Что НЕ утверждается

У стороннего router может быть собственный формат загрузки, отличный от обычного `POST /files`. Если после добавления multipart-поля `model` он вернёт другую ошибку, необходим его ответ/документация. Локальные тесты не доказывают успешную загрузку на реальном router, поддержку `input_file.file_id`, Code Interpreter, background/retrieve и получение ZIP-artifact.

## Повторный запуск

Установить *полный* V188.114 и перезапустить процесс. Старый job из журнала уже имеет статус `failed`, поэтому отправить входной минимальный VK ZIP заново одним документом с подписью/командой Astra. Убедиться в строках `input-file-uploaded` с `inputFileId`, затем `astra-running` с `responseId` и, в конце, `ready-to-send` / `sent`. Не публиковать в логах API-ключи, содержимое ZIP или полный prompt.

## Тестовая совместимость

Исторические тесты V188.102, V188.103, V188.106–V188.110 ранее требовали одну из фиксированных старых версий в `buildVersion.js`; их единственные проверки версии переведены на сравнение `V188.<число> >= версии появления функции`. Остальные assertions оставлены без изменений.
