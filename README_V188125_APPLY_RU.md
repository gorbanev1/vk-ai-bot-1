# V188.125: восстановление старого TXT по Responses ID и Terra для новых файлов

**Установка:** это накладываемый исходный патч на СУЩЕСТВУЮЩУЮ рабочую папку GIGORAVE, а не автономная сборка. Остановите бот и сделайте полную резервную копию его папки, включая `.env`, `data/astra-text-jobs`, все SQLite и файлы outbox. Распакуйте ZIP поверх рабочей папки без удаления файлов, отсутствующих в пакете. Пользовательские данные/ключи не включены в пакет. Проверьте `[BOT BUILD] V188.125` после запуска.

## Что происходит со старой платной генерацией

В логе владельца V188.124 зафиксирован известный responseId
`resp_0b3d23c37cd3774e016aae992d1b8c87d292ed5ecc668b6ffa`
для логического задания
`astra-text:d0e42598-b6f5-4c34-8e8b-c7e51877b144:full`.
При успешном подключении Telegram на следующем старте код делает ТОЛЬКО
`GET <OPENAI_COMPAT_BASE_URL>/responses/<existing-ID>` с исходным compat ключом.
`POST /responses` для этого восстановления НЕ вызывается.

Если сервер вернул `status=completed` И полный непустой output, ответ сохраняется в
`data/astra-text-jobs/<jobId>/full/answer.txt` с SHA-256, затем бот отправляет владельцу
`GIGORAVE_RECOVERED_TEXT_ANALYSIS.txt` по Telegram и помечает доставку. При статусе
`in_progress` проверка продолжается последовательно. По окончании установленного
окна ожидания журнал остаётся доступным для следующего запуска.

Если роутер НЕ даёт GET для старых streaming Responses (HTTP 404/405/410 и т. п.),
или не сохранил ответ, **восстановить именно старую платную генерацию невозможно**:
бот сообщит об этом владельцу, не создавая фиктивный TXT и не начиная новый POST.
Для нового анализа исходный TXT придётся прислать повторно; новые TXT/MD-задания
по умолчанию используют `gpt-5.6-terra`, опционально `gpt-5.5`, без изменений ZIP-аудита.

## Настройка и диагностика

Нужны уже существующие `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_USER_ID` (либо один из
предусмотренных альтернативных env-параметров) и исходный `OPENAI_COMPAT_API_KEY`;
для старого responseId используется ключ старого запроса. Не публикуйте эти значения.
При рестарте ищите `[TEXT RECOVERY STARTUP]` и `[TEXT RESPONSE RECOVERY]`.
Статусы `polling`, `delivered`, `get-unavailable`, `remote-failed`, `poll-exhausted`
разделяют продолжающуюся работу, реальную доставку и неподтверждённый результат.
Не отправляйте файл ещё раз, пока бот проверяет прежний ID.

**Ограничения:** локальные mock-тесты не подтверждают поддержку GET сторонним роутером
или успешность реальной отправки Telegram. При сбое после принятия Telegram-документа,
но до записи отметки доставки, возможен повтор документа после рестарта.
Новые TXT в явном режиме `gpt-5.5`/`gpt-5.6-terra` и старое Astra-восстановление —
разные задания: переключение модели не может продолжить прежний ID.
