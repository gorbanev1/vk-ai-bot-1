Gigorave V134 — VK event photos: reliable delivery parity with Telegram

Исправлено по кейсу, где одна и та же карточка тусы в Telegram приходит с афишей, а во VK — только текстом.

Причина:
- Telegram отправлял уже сохранённый локальный файл напрямую через sendPhoto.
- VK для тех же event image paths использовал отдельный старый one-shot vk.upload.messagePhoto без contentType/contentLength, без проверки attachment и без резервного direct multipart upload.
- Ошибка загрузки ловилась уровнем карточки, поэтому текст всё равно отправлялся, а фото тихо пропадало.

V134:
- VK event posters переведены на тот же hardened image-upload pipeline, который уже используется для сгенерированных картинок.
- Передаются Buffer, MIME type, content length и filename.
- Результат нормализуется и валидируется как photo<owner>_<id>.
- Если vk-io upload не сработал, автоматически выполняется photos.getMessagesUploadServer -> multipart -> photos.saveMessagesPhoto.
- Кэш attachment теперь разделён по VK-сообществам, чтобы основной Гигорейв и второе VK-сообщество не переиспользовали чужой cached attachment.
- Telegram путь не менялся: локальная афиша по-прежнему отправляется одним media-сообщением с caption.

Проверки:
