# V188.142 — устранение блокировки всех источников командой «парсер всё»

Причина установлена по реальному коду V188.141: `startAllManualScraperSources` сортировал источники по chat history-backfill, выдвигая c22 в начало; **каждый последующий VK** ждал `priorVkCaptureWaiter.promise`, то есть завершения всего raw-capture c22, **перед** собственным интервалом 10–20 с. Дополнительно для c22 штатный проход запрашивал не 20, а до 300 initial messages и 50 более старых CMID; `maxDurationMs: 0` запрещал ограничение времени. Исправление прежнего повторного DOM-скролла в V188.141 не устранило эту независимую блокировку.

Изменения:

* Сохраняется порядок источников из конфигурации, больше нет сортировки c22 в начало.
* VK-источники резервируют очередь открытий, но **следующий ждёт только старт предыдущего VK и отдельный случайный интервал 10–20 секунд**, а не завершение его парсинга или DOM-снимка. Telegram сохраняет свою отдельную схему запуска. Глобальный barrier «все raw caches → poster gate → обработка» остаётся: AI/vision не начинают работать во время сбора.
* Для **c22 только в общей команде «парсер всё»** целевой объём равен 20 сообщениям; дополнительный history-backfill этой беседы выключен. Ручной индивидуальный запуск и другие VK-беседы сохраняют свои настройки.
* Каждая VK-беседа в общем проходе имеет ограничение времени захвата по умолчанию 180 с; `MANUAL_PARSER_CHAT_CAPTURE_MAX_MS` позволяет установить 30000–3600000 мс. Контроль проводится между операциями браузера, поэтому это не гарантия точного тайминга зависшей операции Playwright. При превышении сохраняется уже собранное, источник помечается как `timedOut` / неполный, обработка исходных событий продолжается.
* На запуске печатаются и записываются реальные настроенные source ID / count; если в основном пуле не 16, фиксируется `run.source-count-mismatch` — код не создаёт отсутствующие источники и не меняет `.env`.
* Никакие stage admission, event AI/vision, изображения, база и ранее добавленные DOM forensic snapshots не удалены.

Ограничения: нет журнала с текущего компьютера и доступа к его `.env`, поэтому факт **именно 16 активных источников** и успешный полный живой проход не проверены. Новая независимая последовательность запуска повышает число одновременно открытых вкладок VK и расход ресурсов; при нехватке памяти Chromium нужен лог/телеметрия и отдельный лимитер. По-прежнему невозможно гарантировать, что каждая сторонняя страница VK завершит парсинг, если браузерные вызовы зависают насовсем.
