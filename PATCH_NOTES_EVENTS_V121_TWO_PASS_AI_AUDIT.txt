Gigorave Events V121 — two-pass provider-aware AI audit

Owner command remains:
  Гигорейв тест всех моделей

Scope:
- The audit now intentionally excludes OPENAI_COMPAT_API_KEY: this is the owner's already-known working GPT endpoint.
- GigaChat is not part of this command and is not retested.
- Optional extra exclusions can be specified with AI_AUDIT_EXCLUDE_ENV_NAMES=name1,name2.

Latest V120 log analysis that motivated V121:
- 40 keys were present in the old audit, one of them OPENAI_COMPAT_API_KEY (owner endpoint).
- Excluding the owner endpoint leaves 39 foreign keys.
- 30 foreign keys are definitively invalid by explicit provider authentication errors:
  * 26 OpenAI keys: HTTP 401 / Incorrect API key
  * 2 Anthropic keys: HTTP 401 / API key is invalid
  * 2 Gemini keys: HTTP 400 / API key not valid
- 9 foreign keys are NOT treated as dead and therefore remain eligible for real retesting:
  * OpenAI API key slots 1 and 13 (catalog works; inference mostly quota/billing 429)
  * Gemini slots 1, 2, 3 (project/API/referrer restrictions, not invalid-key proof)
  * Groq slots 1 and 2
  * Hugging Face slot 1
  * NVIDIA slot 1
- V120 confirmed 31 text runtime modes (21 NVIDIA + 10 Groq) and 1 Hugging Face image mode, but the old failure list was not definitive because V120 used generic reasoning/payload assumptions.

V121 behavior:
- Round 1 still tests baseline non-stream + real stream/SSE concurrently.
- Reasoning/intelligence levels are provider/model-specific instead of blindly trying every generic level on every model.
  * Groq/HF GPT-OSS: low, medium, high
  * Groq/HF Qwen3: explicit none plus implicit/default baseline
  * NVIDIA GPT-OSS: low, medium, high
  * NVIDIA Qwen3: explicit none plus implicit/default baseline
  * unrelated NVIDIA/Groq models are no longer punished by unsupported reasoning_effort probes
- Baseline is stored as `default`, not falsely labeled as explicit `none`.
- A successful HTTP response is accepted only when the test model actually returns the marker GIGORAVE_AUDIT_OK.
- NVIDIA/Groq/HF OpenAI-style chat probes use max_tokens instead of forcing max_completion_tokens; this fixes a real family of NVIDIA 400 validation errors seen in the V120 report.

Automatic round 2:
- Explicit invalid-key proof is definitive and is NOT pointlessly retried.
- Ambiguous failures are retried automatically after round 1:
  * timeout/network
  * HTTP 429 quota/rate/billing state
  * HTTP 5xx
  * HTTP 404 model/endpoint mismatch
  * HTTP 400/405/415/422 payload/endpoint mismatch
  * access/restriction errors that are not proof of an invalid secret
- For OpenAI-style providers the second round tries provider-appropriate alternative endpoints:
  * NVIDIA: Responses -> Chat Completions -> Completions
  * Groq: Responses -> Chat Completions
  * Hugging Face conversational router: Responses -> Chat Completions
  * OpenAI foreign keys: Responses -> Chat Completions; legacy instruct-like ids may also try Completions
- Terms-acceptance blocks and explicit stream-not-supported results are recorded as known restrictions rather than calling the whole model dead.
- Gemini project/referrer restrictions are retried once for confirmation but V121 does not spoof/bypass provider access restrictions.

Runtime registry:
- ai_runtime_modes is replaced only after a fully completed audit.
- Only combinations that produced a verified successful response after either round are retained.
- If both transports work: prefer non-stream, stream fallback.
- If only stream works: prefer stream, emergency non-stream retry once.
- If only non-stream works: prefer non-stream.
- If neither works after the relevant tests: the combination is absent from the runtime registry.
- A quota/restriction failure is absent from runtime but is not mislabeled as permanently dead in the report.

Reports:
- report.txt / report.json include round-2 counts.
- retry_candidates.json now means remaining failures AFTER automatic round 2 and contains first/second-round status where available.
- AUDIT_DONE.json is the definitive completion marker.
- Telegram final message explicitly reports round-2 attempts and recoveries.
