V117 — canonical post-event feedback schema migration

Fixes startup crash on legacy databases where post_event_feedback_requests has no id column:

  Error: no such column: id

V117 no longer assumes that all historical V109/V110 tables share the same schema.
At startup, before prepared statements are created, it:

1. Adds feedback_received_at when missing.
2. Verifies the canonical id column and composite UNIQUE key.
3. Rebuilds only post_event_feedback_requests when needed.
4. Preserves and deduplicates existing recipient rows by:
   campaign_key + platform + endpoint_key + external_user_id.
5. Recreates the pending-feedback index.

No user review text, coords requester statistics, QR settings, events, or other bot data are deleted.
The migration is idempotent and is skipped once the canonical schema is already present.
