Gigorave Bot V140 install/update

1. Stop the bot.
2. Back up your local .env and data/bot.sqlite.
3. Overlay V140 over the existing V139 project, or use Gigorave_bot_V140_full.zip as the new source tree.
4. Do NOT replace/copy from the release archive into your local:
   .env
   data/
   data/bot.sqlite
   scraper-browser-profile / user browser data
5. Install dependencies if required:
   pnpm install
   (or your existing npm workflow)
6. Validate:
   npm run check:syntax
   npm run check:imports
   npm run check:docs
   npm run test:v140
7. Start the bot.
8. Smoke test the exact bug:
   - open “➕ Предложить тусу”;
   - send the exact VK wall URL of an event that is ALREADY stored but has no poster/old information;
   - expected response starts with “Этот анонс уже есть в базе. Обновляю...”;
   - expected result: existing row updated, no duplicate proposal, source poster saved if VK returns it;
   - request “Тусы” and confirm the refreshed event now uses the source poster.

Optional timeout settings (defaults are already safe):
EVENT_SOURCE_REFRESH_TIMEOUT_SECONDS=15
EVENT_PROPOSAL_AI_TIMEOUT_SECONDS=45

V140 contains no database migration for this fix. Your existing SQLite file is preserved and rows are updated only when the submitted canonical source URL matches them.
