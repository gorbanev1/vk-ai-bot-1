Gigorave V188.55 — установка

1. Остановите текущий процесс бота.
2. Сохраните резервную копию вашего рабочего каталога `data/` и `%LOCALAPPDATA%\Gigorave\state`.
3. Распакуйте V188.55 поверх исходников проекта. Не заменяйте ваш рабочий `data/` содержимым архива: релиз не содержит рабочую БД.
4. Запустите как обычно.

На ПЕРВОМ старте V188.55 бот автоматически очистит только старые обработанные диагностические логи:
- data/logs/
- data/audit/media/
- data/ai-token-usage/
- data/event-ingest-audit.jsonl
- AI_FULL_AUDIT_RESULTS/
- GRAPHICS_MATRIX_RESULTS/

База сообщений, backup'ы, журналы сообщений, WAL/SHM, operation checkpoints и `%LOCALAPPDATA%\Gigorave\state` НЕ удаляются.

После очистки появится строка:
[V188.55 OLD LOG CLEANUP] removed=... missing=... errors=0 ...

Обычный последующий restart логи уже НЕ очищает. Если нужно намеренно повторить очистку, один запуск можно сделать с FORCE_V18855_LOG_CLEANUP=1.

После старта воспроизведите проблемный reply/repost с картинкой. Новые `data/logs/operations` и `data/audit/media` будут содержать только свежий V188.55 прогон, поэтому следующую ошибку можно будет диагностировать без старого шума.
