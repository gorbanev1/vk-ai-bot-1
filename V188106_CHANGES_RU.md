# Gigorave V188.106 — устойчивый Astra-аудит больших ZIP-проектов

## Что исправлено

V188.104/105 мог начать многочасовой аудит ZIP, успешно разобрать несколько больших пакетов, а затем потерять весь job из-за HTTP 524 / Proxy Read Timeout. Кроме того, один параллельный worker мог продолжить тратить токены уже после того, как другой worker завершил `Promise.all` ошибкой и Telegram сообщил, что аудит остановлен.

V188.106 меняет сам алгоритм долгого project-audit:

- project-audit теперь запускается отдельной supervised operation и больше не привязан к двухчасовой жизни входящего Telegram update;
- максимальный срок фоновой операции — 24 часа;
- для Astra project-audit сначала используется Responses `background=true` с polling по `response_id`; это не требует держать один HTTP stream открытым много минут;
- если OpenAI-compatible router не поддерживает background Responses, capability определяется один раз и job автоматически переходит на streaming;
- streaming project-audit больше не переключается автоматически в non-stream после timeout;
- HTTP 408/429/5xx/524, network reset, timeout и временные proxy ошибки повторяются локально и не отравляют глобальный health Astra;
- большие batch уменьшены с ~560k символов до ~96k; chunk — до ~48k;
- если batch всё равно не проходит, он автоматически делится на две части; один большой chunk также режется пополам;
- минимальные leaf-пакеты получают до 12 восстановительных попыток с exponential backoff;
- по умолчанию используется один Astra worker, чтобы не создавать конкурирующие огромные max-reasoning запросы;
- `runWithConcurrency` теперь ждёт завершения уже стартовавших worker-ов перед terminal failure: больше нет ситуации «Telegram сказал stopped, а соседний batch продолжает тратить токены»;
- после каждого batch сохраняется checkpoint в `data/audit-jobs/<jobId>/state.json` и operation checkpoint;
- финальные findings проходят иерархическое сжатие маленькими Astra-вызовами перед final plan, чтобы synthesis сам не упёрся в размер prompt/proxy timeout;
- patch-контекст одного файла ограничен 160k символов вместо 720k;
- JSON planner/patch ответы имеют отдельные повторы на случай битого/truncated JSON.

## Что это значит для пользователя

Временный `524`, `429`, timeout или разрыв соединения больше не должен завершать весь аудит. Бот повторит запрос, а при повторной проблеме раздробит конкретный пакет и продолжит тот же job. Терминальная остановка остаётся только после исчерпания восстановительных попыток или при постоянной ошибке конфигурации/авторизации/несовместимом запросе.
