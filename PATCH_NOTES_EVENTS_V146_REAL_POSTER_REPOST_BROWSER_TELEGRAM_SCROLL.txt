V146 — REAL VK POSTER RECOVERY + TELEGRAM HISTORY SCROLL UP

1. Убрана выдача самодельных event-card.
   - prepareEventImages() по умолчанию больше не генерирует fallback-карточку.
   - getEventAttachments() игнорирует старые generated event_message_cards и слишком слабые локальные изображения.
   - если реальную афишу найти не удалось, пользователю уходит текст события без фальшивой картинки.

2. VK: восстановление афиши через цепочку репоста в Chromium.
   - точный wall-пост сначала читается через VK API;
   - API теперь возвращает relatedWallUrls из copy_history и признак imageConfidence;
   - link-preview не считается надёжной афишей;
   - если photo attachment нет, Playwright открывает исходную wall-ссылку;
   - затем переходит на оригинальный пост репоста;
   - затем открывает паблик владельца оригинала и медленно листает ленту;
   - кандидат выбирается по совпадению даты события + названия/участников/места;
   - найденный пост докручивается в viewport, lazy-media догружается, сохраняется одна лучшая реальная картинка.

3. Найденная афиша сохраняется обратно в существующую запись БД.
   Это не одноразовая косметика сообщения: последующие запросы используют уже исправленную карточку. Старый verified snapshot инвалидируется штатным source-refresh pipeline.

4. Повторная отправка владельцем уже сохранённого VK-анонса и массовое «перепарсить по ссылкам» используют тот же browser recovery, если exact wall/repost не содержит реального photo attachment.

5. Telegram public browser parser теперь догружает историю движением ВВЕРХ.
   settleScraperPage() получил scrollDirection. Для t.me/s/* используется scrollDirection='up'; VK и остальные источники сохраняют downward-поведение.

6. Regression tests:
   npm run test:v146
   + V139/V140/V131/V113 compatibility checks.
