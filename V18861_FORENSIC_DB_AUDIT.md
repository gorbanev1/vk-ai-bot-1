# V188.61 — forensic-аудит реальной `bot.sqlite` и `vk_announcements`

Проверен присланный SQLite family snapshot (`bot.sqlite` + WAL + SHM) и каталог `vk_announcements` в read-only режиме.

## Состояние snapshot

- `PRAGMA quick_check`: **ok**.
- `vk_source_posts`: **165** строк.
- `vk_events`: **23** строк.
- Найдено fingerprint URL с `ava=1`: **145**.
- Найдено fingerprint URL с `type=audio`: **12**.
- Event-строк без poster path: **3**.
- Event-строк, в которых локальный файл совпадает SHA-256 с известным VK UI/avatar/audio fingerprint: **5** (`7, 48, 49, 57, 64`).

Это логическая/media-проблема, а не следствие битого присланного snapshot: SQLite quick-check проходит.

## Подтверждённые реальные случаи

### `liverpool_pub_vrn/2705`

В БД три будущих события и у всех `image_paths_json=[]`:

- 19.09 — Алексей Вдовин → правильная локальная афиша `2705-3.jpg`;
- 20.09 — Игорь Лисов → `2705-1.jpg`;
- 26.09 — Алексей Панасовский → `2705-4.jpg`.

В каталоге эти афиши физически присутствуют. Старый parser сохранил post-level изображения, но не привязал их к event-level карточкам.

### `rb_diesel/13738`

Исходный post — расписание с **10 самостоятельными событиями**: две карточки 12.09, затем 17.09, 18.09, две 19.09, 25.09, две 26.09 и 27.09. В `image_urls_json` сохранено **10 URL**, но старый `image_paths_json` содержит только **8 файлов**, а `vk_events` содержит **одну** строку: 25.09 с заголовком `запись закреплена` и с ошибочно назначенным `13738-1.jpg` (афиша 12.09).

V188.61 добавляет детерминированный parser `HALL:/BAR:` и не разрешает AI заменить более богатый локальный multi-event parse результатом из одной карточки.

### `idmamaanarchy/866`

Единственная сохранённая event-картинка `866-1.jpg` имеет SHA-256, соответствующий fingerprint URL с `ava=1`; визуально это квадратный логотип паблика «Мама Анархия», а не афиша Вадима Курылёва. V188.61 на выдаче блокирует такой файл немедленно, а `парсер все` удаляет/заменяет его при repair-pass.

### `idmamaanarchy/1137`

У события сохранены `1137-1/2/3.jpg`; `1137-2` и `1137-3` совпадают с `ava=1`. Настоящая афиша — `1137-1.jpg` (1080x1528). Старый dimension-score мог выбрать квадратный 1440x1440 логотип. V188.61 исключает известные UI/avatar SHA до выбора лучшей картинки.

### `idmamaanarchy/1142`

`1142-1.jpg` — реальная афиша, `1142-2.jpg` — 1440x1440 avatar/logo (`ava=1`). V188.61 не позволяет логотипу участвовать в display selection и очищает его на repair-pass.

### `rb_diesel/13727`

`13727-1.jpg` — реальная афиша Placebo/MCR (1080x1529), а event сейчас ссылается только на `13727-2.jpg`, который совпадает с `ava=1` (240x240). V188.61 отбрасывает avatar URL/hash и при `парсер все` повторно использует clean stored source URL, поэтому пост может быть починен даже если текущий DOM не отдал картинку.

## Что изменено в V188.61

1. `парсер` / `парсер все` повторно обрабатывает **каждый DB-known VK event post**, а не только тот, у которого прямо сейчас DOM уже показал poster.
2. При repair-pass объединяются clean current URLs и clean `image_urls_json` из `vk_source_posts`; старые URL становятся forensic fallback.
3. `ava=1`, `type=audio`, emoji/reaction/sticker и tiny-only UI assets отбрасываются до fingerprint/vision/download.
4. Старые event image paths сверяются по SHA-256 с UI/avatar fingerprints. Такой путь удаляется; если новой афиши нет, лучше карточка без фото, чем ава паблика.
5. Выдача `тусы` также имеет defense-in-depth: известный UI/avatar SHA не может победить нормальную афишу по размеру.
6. Diesel-style `DD.MM -> HALL:/BAR:` разбирается в несколько событий, в том числе несколько событий на одну дату.
7. Если локальный deterministic parser нашёл больше событий, чем AI, более богатый результат сохраняется; AI больше не может схлопнуть 10 анонсов в один.
8. Event-parser timeout имеет hard floor 60 секунд. Старое окружение с `EVENT_PARSER_AI_ATTEMPT_TIMEOUT_SECONDS=25` больше не обрывает рабочую vision/text модель на 25-й секунде.
9. Максимум изображений одного source-post остаётся 12; для `rb_diesel/13738` это позволяет пройти всем 10 исходным URL.

## Как применить repair к этой БД

После установки V188.61 выполнить вручную:

`Гигорейв парсер все`

Это не требует ручного удаления текущих `vk_events`: известные source-posts становятся repair candidates. Частичный reparse не удаляет unmatched stored events; уверенно сопоставленные poster paths обновляются. Для старых avatar paths действует отдельная очистка по SHA.
