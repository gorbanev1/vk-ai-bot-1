GIGORAVE V155 — DURABLE AUTO-SUMMARY STATE

Problem fixed
-------------
V154 stored auto-summary settings in data/bot.sqlite inside the release tree. A process restart was fine, but replacing the whole bot directory or starting a freshly unpacked full build could point the new version at a new bot.sqlite and make an enabled auto-summary look disabled.

V155 contract
-------------
1. Auto-summary settings are now source-of-truth in a dedicated SQLite database outside the release directory.
2. Stored fields per chat: peer/platform/endpoint, mode, enabled flag, next_run_at, updated_by, updated_at.
3. Completed auto-summary slots are stored there too, so replacing release files does not cause the same scheduled slot to be sent twice.
4. Windows default: %LOCALAPPDATA%\Gigorave\state\auto-summary.sqlite (fallback %APPDATA%).
5. Linux default: $XDG_STATE_HOME/gigorave/auto-summary.sqlite or ~/.local/state/gigorave/auto-summary.sqlite.
6. Optional override: GIGORAVE_STATE_DIR=<absolute stable directory>.
7. On first V155 start, rows from legacy data/bot.sqlite are migrated automatically when that database is present. New V155 writes are mirrored to legacy bot.sqlite for rollback compatibility.
8. On every startup enabled rows are loaded immediately; a malformed enabled row with next_run_at=0 is repaired to the next valid slot instead of silently never firing.
9. Startup log prints [AUTO SUMMARY DURABLE STATE] with DB path and number of enabled chats.

Recommended upgrade from a currently running V154
-----------------------------------------------
Apply the V154 -> V155 patch over the existing installation once. This lets V155 migrate the currently enabled V154 record into the user-level durable database. After that, future full-release file replacement no longer affects auto-summary state.

Verification
------------
1. In a group: `авторезюме` or `авторезюме только вечер`.
2. Check: `авторезюме статус`.
3. Stop the bot. Replace/re-unpack application files. Do not touch the user-level Gigorave state directory.
4. Start the bot.
5. `авторезюме статус` must still report enabled with the same mode and next run.
