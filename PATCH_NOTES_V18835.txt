Gigorave V188.35 — current VK DOM exact parser + prefilter/trace patch

Основание патча: фактический DOM и trace прогона chat:2000000022 от 2026-09-10.

VK Messenger
- Полный DOM каждого VirtualScroll-окна сохраняется ДО exact parsing; Stage 1 читает тот же immutable HTML.
- Exact Stage 1 использует VirtualScrollItem[data-itemkey] как CMID.
- Содержимое разделено на contentText и repostText. UI author/time/publish metadata не смешиваются с текстом анонса.
- Для актуального DOM wall/repost тело берётся из AttachWallNew__message; AttachWallNew__subtitle не считается текстом события.
- Настоящие media ищутся по attachment/photo context; avatar/emoji/reaction/icon/logo/users-stack отбрасываются.
- Snapshot-exact media имеет приоритет над rendered fallback, чтобы merge не возвращал UI-картинки.
- Backfill остаётся по initialMinCmid и считает только CMID ниже первоначального frontier.
- Убрана вторая 1.8s media-пауза на каждом history-окне: сохраняется обязательная 1.8s slow-scroll pause, тяжёлый media settle выполняется перед финальным immutable capture.
- В trace добавлен source.history.scroll.

VK Public
- Полный DOM сохраняется до Stage 1.
- Exact Stage 1 разбирает [data-testid="post"][data-post-id], post-content-container, showmoretext, post_date_block_preview.
- Отдельно извлекается самый глубокий вложенный repost.
- Media ownership: собственный primary attachment внешнего поста всегда выше nested repost; nested media используется только если своей афиши нет.
- Legacy regex оставлен только fallback после current-DOM exact parser.
- Current exact text/media не заменяются rendered UI-шумом.

Event candidate gate
- UI-время публикации/сообщения больше не может сделать запись кандидатом.
- Текстовый кандидат: реальная дата внутри content/repost текста.
- Visual candidate: только структурно признанная media/афиша.
- Repost может пройти hydration как структурное подозрение, но AI вызывается только после появления даты либо настоящей poster-media.

Diagnostics / AI
- item.processing.queued -> item.processing.slot -> item.processing.start -> fulfilled/rejected.
- queueWaitMs и состояние общего limiter пишутся в trace.
- Failover моделей пишет sanitized события в trace: provider/key name/model/mode/attempt/round/retryable/wait/error без секретов ключей.
- Две технические попытки на ступень модели и существующая лестница проекта сохраняются.
