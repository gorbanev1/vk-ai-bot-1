Gigorave V187 — no-repeat AI personalization / parser hotfix

Base: V186
Version: 0.187.0
Build: events-v187-batched-personalization-no-repeat

What changed
1. Removed daily/startup GPT dossier/style backfill.
2. Dossier is command-only. It processes at most 400 new messages per paid batch and persists a checkpoint after every successful batch.
3. Re-running dossier with no new messages uses the saved dossier and makes 0 GPT calls.
4. Automatic communication-style refresh waits for 500 NEW messages for that user. Existing history is checkpointed without GPT on first V187 observation.
5. Background style generation is globally rate-limited so it cannot create a startup burst of model calls.
6. Personalization checkpoints live in a durable SQLite store separate from bot.sqlite, so restoring/replacing the main DB does not automatically replay already-paid personalization work.
7. Public-post content identity no longer includes PARSER_VERSION. Upgrading the bot does not reparse unchanged Telegram/VK posts just because the release number changed.
8. Legacy V184/V185/V186 version-coupled hashes are recognized for compatibility, avoiding one last forced reparse during migration.
9. Intentional full event reparse is explicit through GIGORAVE_EVENT_REPARSE_EPOCH.

Validation performed for release packaging
- Targeted regression suite: 20/20 passed.
- Covers V187 personalization policy, durable state, source-content hash, dossier access/output, V148 regression checks, V186 image fingerprint behavior, and V185 event date/audit repairs.

Important
- Patch is intended for V186.
- Keep your existing data/ directory and production bot.sqlite/WAL/SHM when applying the patch.
- Do not copy a bundled example/empty database over production data.
