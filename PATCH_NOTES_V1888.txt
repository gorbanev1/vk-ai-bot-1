Gigorave V188.8 — finite public parsing + early VK event bootstrap + full-page fallback

Build: events-v1888-finite-vk-parser-early-bootstrap-fallback
Version: 0.188.8
Base: V188.7

Fixes
1. Public VK/Telegram manual source runs are finite by default. The browser tab is no longer used as a hidden stop button and is closed after the pass. Only VK chat sessions remain intentionally live until their chat tab is closed. `SCRAPER_KEEP_MANUAL_SOURCE_TABS_OPEN=true` can still explicitly restore diagnostic live-tab behavior for public sources.
2. Event/proposal links also use a finite browser pass by default and close their tab in `finally`, including error paths. Normal event parsing no longer waits for the owner to close Chromium.
3. VK event structured data is snapshotted immediately after DOMContentLoaded, before scrolling and before the SPA can consume/replace `apiPrefetchCache`.
4. The first pass reads both current runtime objects and JSON-shaped bootstrap data from the original page HTML. It prefers `apiPrefetchCache` when present but does not depend on one exact `groups.getById` template; generic application/json bootstrap objects are also supported.
5. Structured VK event data is used first for deterministic fields such as `start_date` -> date/time. The parser still performs the normal DOM/meta/body/post pass afterward and merges the strongest generic page evidence to fill missing fields such as venue, participants, price and description.
6. A whole-page VK fallback candidate is retained when structured data exists but the current VK DOM no longer exposes a conventional post container.
7. Common schedule lines in the form `ПЛОЩАДКА, 19 сентября в 19:00` now deterministically recover the venue. For the reproduced page this yields date `2026-09-19`, time `19:00`, and venue `КОТЕЛЬНАЯ` before AI fallback.
