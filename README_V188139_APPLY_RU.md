# Gigorave V188.139 — один эталонный VK DOM для изучения структуры + полный журнал прохода

## Что именно снимает команда «парсер всё»

Для КАЖДОГО настроенного источника VK при ручном полном проходе бот создаёт один отдельный **структурный baseline ещё до первой прокрутки текущего парсера**. После него обычная команда продолжает работать как раньше. Это не новый парсер, не вторичная загрузка VK и не повторная прокрутка для диагностики. В «парсер всё» также остаются все поскролльные raw DOM-снимки V188.138 и журналы текста/изображений V188.137; они нужны для другой задачи — полного сбора ленты и причин потери афиш.

Ищи в каталоге проекта после запуска (имена источника и runId в действительности подставятся автоматически):

```text
data/parser-forensic-archives/<runId>/
  trace.jsonl                               # события vk.fixture.persisted и vk.structure-baseline.failed
  vk-dom-structure-baselines/               # одна исходная вкладка на источник до скролла
    vk-<source>-<hash>/
      dom.raw.html                          # исходный полный document.documentElement.outerHTML
      dom.structure.json                    # все элементы, атрибуты, прямые текстовые узлы,
                                          # parentIndex и цепочки предков найденных wall-ссылок
      page-state.json                      # URL, baseURI, время, scrollY, viewport, SHA-256,
                                          # проверка quiet/timeout
      resources.json                       # href, src, srcset, data-src, currentSrc и т. п.
      manifest.json                        # SHA-256, длина HTML, перечень файлов
      PROMPT_FOR_DOM_AUDIT_RU.txt           # готовое задание для другого чата
    chat-<peer>-<hash>/
      ...                                   # отдельный baseline для VK-беседы
  vk-dom-fixtures/                          # старые полные слепки КАЖДОЙ итерации парсера
    <source>/manifest.json
    <source>/iterations/000001/dom.html
    <source>/iterations/000002/dom.html
    ...
  poster-forensics/                         # существующий V188.137 журнал картинок
```

Папки создаются **после** запуска команды, не при установке. Начальное положение вкладки фиксируется в `scrollY`: «до прокрутки» означает до прокрутки, запрошенной этим проходом, а не обязательно `scrollY=0` (VK может открыть беседу посередине). Ожидание тишины DOM: 600 мс, но не дольше 4,5 секунды. Если VK продолжал изменять страницу, `page-state.json.quiet.stable=false`; такой baseline НЕ выдаётся за стабильный. «DOM тихий» не доказывает, что все посты уже загружены.

`dom.raw.html` — PRIMARY GROUND TRUTH: ни CSS-классы, ни атрибуты, текст, вложенность, порядок узлов не очищаются. `dom.structure.json` — отдельно записанная аналитическая проекция увиденных элементов; ссылки-кандидаты и цепочки их предков — только подсказки для аудита, а НЕ подтверждённые карточки/шаблон и НЕ вывод старого парсера. Разбор должен начинаться с raw HTML и доказать, откуда берётся каждое поле. Файлы `expected/announcements.json`, `template.json` и «идеальный парсер» НЕ генерируются по догадке: нужен твой реальный слепок и независимая разметка примеров. Одного baseline может не хватить для изучения всех типов карточек (репост, 5 фото, длинный текст): тогда нужны реальные дополнительные исходные страницы/итерации.

## Как установить и получить данные

1. Сделай резервную копию текущего проекта, всей `data/`, БД с WAL/SHM и `.env`. Дождись конца других задач. Останови бот.
2. Распакуй накопительный архив V188.139 в корень проекта с заменой **только перечисленных кодовых файлов/документов**. ZIP не содержит `data/`, БД, изображений, токенов и профиля браузера. При наличии собственных правок в этих файлах сначала сравни их с архивом — простая перезапись их затрёт.
3. Из корня проекта запусти `npm run test:v188139` и проверь обычный запуск бота.
4. В боте запусти штатную команду **«парсер всё»** ОДИН раз. Дождись пока пройдут интересующие источники; при завершении каждого источника его baseline уже записан на диск.
5. Из `data/parser-forensic-archives` выбери последнюю папку запуска. Для анализа **структуры карточек** упакуй `vk-dom-structure-baselines` целиком в ZIP и приложи сюда или в другой чат; вложенный `PROMPT_FOR_DOM_AUDIT_RU.txt` содержит точное задание. Если нужно понять пропуски по всей ленте, отдельно прикладывай `vk-dom-fixtures` и `trace.jsonl`; они могут быть очень большими.

Для офлайн-проверки выбранного baseline (без VK/сети/браузера/AI):

```bash
node scripts/vk-dom-structure-verify.mjs "data/parser-forensic-archives/<runId>/vk-dom-structure-baselines/<source-folder>"
```

Для проверки всех поскролльных слепков источника (старый механизм):

```bash
node scripts/vk-dom-fixture-verify.mjs "data/parser-forensic-archives/<runId>/vk-dom-fixtures/<source-folder>"
```

**Личные данные:** полный VK DOM, особенно бесед, может включать личные сообщения, приватные ссылки и значения элементов формы. Прежде чем переслать `vk-dom-structure-baselines` в другой чат, проверь содержимое выбранных папок; не выкладывай их публично. Удаление/редактирование `dom.raw.html` нарушит SHA-256 и сделает его уже НЕ исходным эталоном. При необходимости снимай отдельный baseline с тестового/публичного источника.

**Ограничения:** реальная VK-страница в тестовой среде не открывалась, поэтому нельзя обещать, что первый baseline будет содержать 3–5 разных типов карточек. Новый код не меняет парсер постов, отбор афиш или доставку, не исправляет пропавшие изображения и не гарантирует полноту всей ленты — он сохраняет доказуемый исходный DOM и отдельную структурную проекцию для разработки офлайн точного контура.
