# Gigorave V188.86 — исправление афиш, дедупа и VK DOM/reload

## Главное

- В публичной карточке может быть **не более одной реальной исходной афиши**.
- Сгенерированные/AI/fallback-картинки больше не создаются и не попадают в выдачу.
- Одна картинка в посте/сообщении сама по себе **не считается афишей**: нужна сохранённая положительная Vision-привязка конкретного `[IMAGE N]`.
- Уже корректная подтверждённая source-картинка имеет приоритет и не заменяется reparsing-ом случайной картинкой.
- Для выбранной афиши в `posterVisionFacts` сохраняются `imagePath`, `imageFilename` и `imageSha256`; кандидаты при merge дедуплицируются по SHA-256, когда хеш доступен.
- Источник может хранить полную media-галерею для forensic/reparse, но event-level `imagePaths` остаётся максимум из одного доказанного poster.

## Исправленные случаи последнего перепарсинга

- Убрано старое правило singleton-source -> вся галерея события. Оно давало 2/4 одинаковых картинок, баннеры, розыгрыши, emoji/sticker рядом с афишей.
- Старые `verified_single_event_source_media`, полученные только по принадлежности источнику, при миграции больше не считаются доказательством poster. Положительные сохранённые Vision facts при этом сохраняют правильную карточку.
- Generated cover больше не может подменять существующую настоящую афишу.
- Служебный текст Vision (`[IMAGE N]`, `Тип изображения`, `Это афиша события`, `[Факты с афиши]`) и URL/ticket links вычищаются из публичного текста анонса.
- QTickets/другие single-event источники не размазывают всю галерею в карточку.

## Дедупликация

- Одинаковая дата + одинаковое нормализованное название объединяются независимо от конфликтующего времени начала.
- При конфликте времени одного подтверждённого события выбирается **самое раннее** время.
- Из identity-title удаляются известные названия площадок, поэтому `STONEHAND ... DIESEL HALL` и `STONEHAND` могут попасть в один дедуп-контур.
- Частичное совпадение по целому содержательному слову названия на одной дате направляет пару во второй AI-контур.
- Жёсткие различия физических площадок сохранены: например `DIESEL Bar` и `DIESEL Hall`, а также конфликтующие номера домов, не склеиваются.
- После подтверждённого merge AI получает все реальные poster-кандидаты и может выбрать **ровно один** `selectedImagePath` только из них. Новые изображения AI не создаёт.
- Полный deterministic registry не заменяется урезанным snapshot-реестром.

## VK capture / DOM

- Основные parser-all источники стартуют с новым случайным интервалом **5–20 секунд**.
- При ошибке загрузки VK: случайное ожидание **10–20 секунд**, затем повторная проверка текущего DOM и только после неё reload; не более 3 reload.
- Если в изменившемся DOM уже есть содержательный текст/media, отсутствие старого exact-selector не вызывает ложный reload.
- Exact-pass использует immutable DOM snapshot, а live `currentSrc` принимается только при строгой identity того же media/post/message.
- Диагностика сохраняет полный HTML и DOM-state: `currentSrc`, `src`, `srcset`, размеры, rect/visibility, attributes, принадлежность post/message, доступные iframe и open shadow DOM, плюс SHA-256.

## Совместимость и защита правильных карточек

- Старые безопасные статусы `exact_poster_match`, `verified_multi_event_poster`, `verified_title_date_poster`, `legacy_manual_poster` не очищаются migration-ремонтом.
- `verified_single_event_source_media` сохраняется только если рядом есть положительный persisted Vision fact для конкретного изображения.
- Media-файлы immutable: другой CDN/currentSrc не перезаписывает существующий файл с другим содержимым.
- Исходная media-галерея остаётся в source-ledger и не теряется, даже когда event-level карточка показывает только одну афишу.
