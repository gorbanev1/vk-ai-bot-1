# GIGORAVE — проверяемая сборка STAGE6 + защита verified snapshot

Эта поставка собрана из всех 20 TXT-частей STAGE6 после проверки SHA-256 исходных файлов. Добавлена узкая проверка допустимой календарной даты **перед записью** verified snapshot: если одна карточка не имеет даты YYYY-MM-DD или дата не существует (например, 2027-02-29), новый snapshot целиком отклоняется, предыдущий файл остаётся нетронутым. Новый тест: `tests/events/finalVerifiedSnapshotDateBoundary.test.mjs`.

Всё остальное по контурy событий — существующая логика STAGE6: захват VK/Telegram → обработка и ledger → dedupe → проверенный snapshot → выдача. Логика Astra/TXT, поток SSE, трассировка, длительность ожидания, параметры reasoning, остановка/восстановление и антидублирование платных POST **не изменялись**. Не добавлялись ни таймаут ожидания содержательного текста, ни watchdog, закрывающий соединение.

## Проверки именно этой поставки

- `node scripts/check-syntax.mjs` — 623 исходных файла до добавления одного нового теста; синтаксис OK.
- `node scripts/check-named-imports.mjs` — OK (221 файла; missing=0).
- `node scripts/check-imports.mjs` — OK.
- 67/67 целевых офлайн-тестов: snapshot, SQLite-атомарность VK Public/Telegram, VK Chat, инкрементальные отпечатки, критерии даты, метаданные афиш и отдельные пулы событий.
- В дополнительном смешанном прогоне 75/77: два исторических теста `eventProvenancePosterV18867.test.mjs` ожидают устаревшее поведение (ссылку на источник в режиме «кратко» и старую форму флага принудительного перепарса), не соответствующее принятой новой логике. Отдельный исторический тест `eventDuplicateResolution.test.mjs` ожидает 19:00, тогда как текущая политика merge выбирает 18:00. **Не подгоняли работающий код под старые ожидания.**

Здесь нет доказательств полного успешного end-to-end прогона на реальных VK/Telegram и платных AI, он не выполнялся. Нельзя считать сборку гарантированно безошибочной до контролируемого запуска и аудита на тестовой/резервной базе.

## Установка и защита данных

Сделайте резервную копию Вашей рабочей папки и отдельно `data/`, `.env`, SQLite, внешних каталогов state. Распакуйте в отдельную директорию или обновите только исходники с сохранением локальных конфигураций и данных. Архив сознательно **не содержит** .env, паролей, SQLite, рабочих логов, node_modules и данных пользователей. На своей машине установите зависимости из package.json/pnpm-lock.yaml соответствующим менеджером пакетов. Для проверки без контакта с VK и платным AI используйте команды из раздела выше. Не подменяйте рабочую базу тестовыми файлами.

Источник сборки: GIGORAVE_STAGE6_20_TXT, а не старый FIX4. Архив содержит все текущие `src/`, `tests/`, `scripts/`, `miniapps/`, корневые package.json и pnpm-lock.yaml, а также QR-asset предыдущей полной поставки. Исторические `payload/src/`, `.patch` и старые копии `botApplication.js` намеренно исключены: они относятся к другой версии и не должны запускаться/путать проверку импортов.
