ЧТО ИЗМЕНЕНО

1. ЖЁСТКИЙ ПРЕДЕЛ АЛГОРИТМА: 2 ЧАСА
- Любой пользовательский запрос Telegram/VK запускается через operation supervisor.
- Долгие detached jobs: parser, summary, maintenance, event snapshot, AI audit, recovery, broadcast и startup diagnostics также запускаются через supervisor.
- DEFAULT_OPERATION_TIMEOUT_MS = 2 * 60 * 60 * 1000.
- Короткие provider/network timeout остаются короткими: 2 часа — последний аварийный потолок, а не штатное ожидание.
- OpenAI/image/network fetch signal объединён с сигналом текущей операции.
- Model failover/retry/backoff теперь тоже слушает AbortSignal: после отмены/2h timeout он не продолжает незаметно переходить на следующие модели.
- Stop handlers имеют собственный предел 15 секунд, поэтому команда остановки сама не может навечно зависнуть на cleanup стороннего SDK.

ВАЖНО: Promise в JavaScript нельзя физически убить, если сторонний SDK полностью игнорирует AbortSignal. В таком случае логическая операция немедленно завершается для пользователя и остаётся видимой как stopping/timed-out-stopping до фактического settle. Инструментированные OpenAI/network/parser/browser контуры получают реальный abort. Позднее settle корректно записывается в лог и снимает операцию из списка.

2. КОМАНДЫ ПРОЦЕССОВ И CHECKPOINT
- «процессы» / «незавершенные процессы» — показать активные/незавершённые задачи.
- «процесс <id>» — показать статус, дедлайн, progress/checkpoint.
- «прервать процесс <id>» — сохранить текущий checkpoint и запросить остановку.
- «прервать мои процессы» — остановить свои активные процессы.
- Владелец: «прервать все процессы» — остановить все доступные процессы кроме самой команды остановки.
- Уже записанные результаты не откатываются.
- Parser all сохраняет total/completed/unfinished, pending candidates, source captures и trace path по ходу обработки. Если обработано 10/20 — эти 10 остаются сохранены, остальные фиксируются как незавершённые.

3. ПОДРОБНЫЙ JSONL AUDIT
Runtime log: data/logs/operations/YYYY-MM-DD.jsonl
Checkpoint files: data/operation-checkpoints/<operationId>.json

Пишутся:
- operation start/complete/failed/cancelled/timeout;
- точное startedAt/deadlineAt/elapsed/status;
- progress/checkpoint и explicit unfinished snapshot на timeout;
- runtime memory/active resources при авариях;
- stop reason и результаты stop handlers;
- unhandledRejection, uncaughtExceptionMonitor, process warning;
- console.error / console.warn (с редактированием ключей/токенов);
- provider success/failure/timeout/operation-abort;
- каждый model failover event: provider/key/model/mode, ladderStep/ladderTotal, attempt, round, retryable, duration, wait, timeoutFailure, error;
- parser source/candidate progress, success/error, checkpoint, finalization, trace path;
- background broadcast/AI audit/vision events и результаты supervised jobs.

Секреты API/token/password/authorization редактируются перед записью.

4. UNIVERSAL IMAGE INPUT
- Telegram/VK вложенные изображения и изображения из reply централизованно обнаруживаются.
- Перед текстовым AI-контуром выполняется vision/OCR preprocess один раз на входящий запрос и кешируется в AsyncLocal request context.
- Распознанный текст/описание добавляется в обычный AI, документы/Word/PDF, вопросные режимы и другие текстовые генерации.
- Бот больше не должен отвечать «списка вопросов нет», если вопросы находятся на приложенной фотографии.
- Для image editor исходная картинка остаётся edit target; vision/OCR дополнительно описывает исходник и обогащает prompt изменения.
- Vision preprocess не рекурсирует сам в себя.
