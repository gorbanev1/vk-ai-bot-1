# Gigorave V188.99 — canonical dedupe + строгий metadata-gate афиш

## Зачем патч

V188.99 закрывает два связанных класса ошибок: в публичной выдаче могли одновременно жить актуальная и устаревшая версия одной карточки, а исторический poster-status/`verifiedImagePaths` в отдельных контурах мог позволить картинке пережить более позднее изменение identity события. Теперь dedupe выбирает одну каноническую версию, а картинка допускается в карточку только через конкретную сохранённую Vision-привязку, которая заново совпадает с итоговым событием.

## Дедуп: неактуальная карточка больше не возвращается

1. Версия deterministic dedupe поднята до `event-dedupe-v18899-canonical-metadata-poster-4`.
2. При merge канонический member выбирается не по порядку источников: высокий приоритет получает карточка с **безопасной выбранной афишей**, затем учитываются poster relevance, полнота metadata, approved-status и наполненность полей.
3. Для одинаковой даты + сильной identity устаревшая metadata-poor версия может быть схлопнута с актуальной metadata-backed версией. Финальный `metadata-anchor sweep` позволяет одной сильной metadata-backed карточке поглотить несколько взаимно конфликтующих старых raw-вариантов, которые из-за complete-link раньше могли пережить дедуп. Каждый такой вариант обязан **напрямую** совпасть с исходным каноническим anchor и сам не иметь безопасной афиши.
4. Если у двух карточек есть собственные безопасные metadata-backed афиши, этот asymmetric sweep их не склеивает. При разных названных площадках supersession разрешён только в случае safe-vs-unsafe и только когда metadata безопасной афиши явно подтверждают её собственную площадку.
5. Защитные различия площадок сохранены: `DIESEL Bar` ≠ `DIESEL Hall`; конфликтующие номера домов — hard conflict; две явно разные названные физические площадки не отдаются AI на произвольную склейку.
6. Verified snapshot больше не реинжектит raw orphan, если тот детерминированно является дублем уже собранной канонической карточки. В аудите такая строка остаётся как `orphan-duplicate-suppressed`.
7. Никакие сырые строки source-таблиц этим патчем не удаляются. Это dedupe/visibility suppression, а не permanent delete, поэтому V188.88 forensic/raw semantics и V188.94 soft/permanent delete не смешиваются.

## Афиша: только релевантная картинка с metadata

1. Публично безопасная картинка теперь требует одновременно:
   - trusted poster status;
   - конкретный `poster_image_index > 0`;
   - persisted Vision fact именно этого индекса;
   - непустой `imagePath` в выбранном Vision fact;
   - **точное совпадение нормализованного `fact.imagePath` с реально renderable path** из карточки;
   - `poster=true`/эквивалентное подтверждение;
   - совпадение даты;
   - event-specific identity по содержательному title/participants.
2. **Дата без identity больше не проходит.** Старый V188.93 fallback `date-only-source-poster` намеренно superseded: одинаковый день у двух разных событий больше не может сделать чужую картинку допустимой.
3. Старый `exact_poster_match`, `legacy_manual_poster` или путь в `verifiedImagePaths` сами по себе больше не дают права рендерить изображение. Metadata нет/не совпадает **или metadata относятся к другому filesystem path** — карточка временно text-only, файл и forensic metadata не уничтожаются. Это закрывает вариант, когда metadata картинки №1 могли бы случайно «освятить» путь картинки №2.
4. При подтверждённом merge все poster-кандидаты повторно оцениваются уже относительно объединённого события. Выбирается максимум одна реальная source-афиша по relevance score, затем по полноте metadata/confidence/readability. Порядок источников не определяет победителя.
5. AI merge может выбрать изображение только среди строго совместимых кандидатов и не может понизить существенно более релевантную/лучше описанную афишу.

## «Вообще все тусы»

V188.88 остаётся отдельным realtime aggregate и QTickets по-прежнему выигрывает duplicate group. V188.99 меняет только перенос картинки: QTickets может взять poster у дубля лишь когда выбранный Vision fact донора строго совпадает и с QTickets-card. Вместе с `verifiedImagePaths` переносится binding metadata, поэтому path-only обхода нет. Среди равноприоритетных aggregate-кандидатов metadata-backed poster также повышает качество winner.

## Совместимость с последними патчами

- **V188.86:** максимум одна реальная source-афиша, никакого generated fallback, SHA/forensic gallery сохраняются; earliest time после merge сохранён.
- **V188.87:** QTickets меню/ценовые фильтры не меняются.
- **V188.88:** `all_party_metadata` остаётся производным индексом; source DB dedupe не заменяется агрегатным; raw tables не мутируются.
- **V188.92:** metadata durability и явная команда `тусы метаданные картинок заполнить` сохранены; старые startup/network repair не возвращены.
- **V188.94:** duplicate suppression не создаёт permanent fingerprints и не подменяет soft/permanent delete.
- **V188.96:** если подтверждённая афиша есть, VK upload failure по-прежнему удерживает карточку; событие без безопасной афиши может быть text-only.
- **V188.97–V188.98:** owner delete/edit, text+image correction и revalidation старой афиши сохранены. Owner search по-прежнему стартует от raw SQLite для полноты поиска, но перед показом нумерованного списка проходит deterministic canonical dedupe, поэтому устаревшие варианты одной тусовки не должны засорять меню. V188.99 делает тот же metadata-gate обязательным во всех публичных merge/render контурах.

### Намеренное изменение старого поведения

Единственное осознанно отменённое послабление — V188.93 `date-only-source-poster`. Оно противоречило более позднему V188.92/V188.98 требованию metadata-совместимости и позволяло same-day нерелевантной картинке попасть в карточку. Теперь дата остаётся обязательной, но недостаточной.

## Эксплуатация после обновления

Для исторических картинок, у которых ещё нет persisted Vision metadata, один раз явно запустить owner-команду:

`тусы метаданные картинок заполнить`

До backfill такие изображения не показываются. Автоматического backfill при старте нет намеренно.

## Регрессии V188.99

Добавлены проверки на: date-only reject; status/path-only reject; **exact Vision-fact path binding**; canonical suppression устаревшей карточки; screenshot-like swarm из шести вариантов; выбор лучшей metadata-backed афиши; запрет `verifiedImagePaths` bypass; безопасный poster donor в `Вообще все тусы`; защиту двух independently-safe карточек на разных реальных площадках. Исторические venue/media tests обновлены так, чтобы ожидаемая картинка тоже имела persisted Vision metadata — согласно текущему контракту.
