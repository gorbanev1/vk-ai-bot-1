V145 — TARGETED THIRD AI RECOVERY SWEEP

V145 adds a separate final recovery pass that consumes the latest completed full-audit report instead of launching the whole audit again.

Owner command:
- Гигорейв третий обход моделей
- aliases: «3й проход апи», «финальный обход ключей»

CLI:
- npm run audit:third-recovery
- force a completely new third pass: npm run audit:third-recovery -- --force

Selection policy:
1. Only key_second_full_sweep rows with verdict=uncertain are reconsidered.
2. Runtime modes that became working only on late retry rounds are control-tested once.
3. Confirmed dead rows, normal stable modes and quota-quarantined keys are not bulk-tested again.

Uncertain-key policy:
- one catalog/auth check;
- only for transient catalog failure: one delayed catalog retry;
- after a successful catalog, at most 6 text + 2 image candidates per key by default;
- one request at a time per exact key; global key concurrency defaults to 2;
- non-stream is tried first; stream is only tried when the first transport did not establish a working mode;
- 429 rate-limit stops further probing for that key instead of multiplying 429s;
- quota/no-credits stops the key and moves it to the V144 quota quarantine;
- 401 invalid may be removed from .env;
- 403/restricted, network, timeout and 5xx are not destructive cleanup reasons.

Late-recovery control policy:
- preferred transport gets one control call;
- fallback/opposite transport is tried only if preferred fails;
- transient failure does not delete a previously working runtime mode;
- if fallback works, preferred transport is switched to the actually working one;
- only explicit model deprecation can remove one model from this control stage; key-wide removal needs explicit invalid credentials.

Crash/restart safety:
- progress is append-only in THIRD_RECOVERY_SWEEP_V145/results.jsonl;
- THIRD_SWEEP_DONE.json marks a complete run;
- after a bot/process interruption, repeating the command resumes and skips completed signatures;
- after DONE, the same command is idempotent and performs no new API calls unless --force is used from CLI.

Outputs are stored under the source full-audit directory:
AI_FULL_AUDIT_RESULTS/<audit>/THIRD_RECOVERY_SWEEP_V145/
- third_recovery_sweep.json
- results.jsonl
- THIRD_SWEEP_STATUS.json
- THIRD_SWEEP_DONE.json

Environment/runtime actions:
- newly discovered no-credit keys -> GIGORAVE AI QUOTA QUARANTINE;
- explicit invalid keys -> .env removal with backup;
- recovered modes are merged into ai_runtime_modes;
- keys with temporary/blocked/rate-limit state are preserved.

V144 quota lifecycle remains unchanged: 5th and 20th, five confirmed no-credit passes, SQLite-backed counters independent of restarts.
