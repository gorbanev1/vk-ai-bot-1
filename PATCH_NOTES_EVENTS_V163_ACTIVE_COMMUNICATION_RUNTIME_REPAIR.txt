EVENTS V163 — ACTIVE COMMUNICATION RUNTIME REPAIR

Root causes fixed
-----------------
1. Active communication used a per-peer Promise queue and the incoming message
   handler awaited that queue. One OpenAI request could remain pending for the
   global 15-minute timeout; every later autonomous message in the same chat
   waited behind the unresolved Promise.
2. Autonomous replies selected only GPT modes pro/pro2. Those modes resolve to
   Luna/Terra defaults without proving that the configured endpoint actually
   serves those model IDs. Normal bot replies could work on the default model
   while every active-communication attempt failed silently.
3. Autonomous sends had no dedicated timeout and command/status diagnostics did
   not show runtime failures.

V163 behavior
-------------
- autonomous generation is detached from the incoming-message handler;
- no permanent per-peer Promise queue;
- 25s AI timeout, 15s send timeout, 45s watchdog;
- stale generations are invalidated by run id and cannot send after replacement;
- model fallback chain: selected pro/pro2 -> alternate -> default -> gpt54 ->
  GigaChat when configured;
- active communication enable/disable/status are direct group fast paths on VK
  and Telegram, without requiring a preceding dialogue session;
- status displays last eligible message, last attempt, last successful reply,
  last model and last runtime error for the current process.

V163 also includes all V162 auto-summary scheduler-watchdog fixes.
