# V188.115 — проверяемый формат `/files`: модель в multipart и URL

## Что показал реальный лог

В V188.114 Telegram уже сохранил и проверил исходный ZIP, собрал sanitized ZIP и выбрал `gpt-6-astra` с `reasoning_requested=max`. Запрос `/files` всё равно завершился HTTP 400 «Model name not specified». В показанном журнале нет `input-file-uploaded`, `astra-running` и `responseId`; свидетельства запуска inference отсутствуют. Отсутствие строк в обрезанном логе не доказывает отсутствие сторонних списаний.

## Исправления

- Проверен фактический код V188.114: `model` УЖЕ передавалась из `generateOpenAITextWithFilesAttempt()` и добавлялась через `form.append('model', modelName)`. Ошибка не сводится к отсутствующему `form.append`.
- В V188.115 ОДИН запрос `POST /files` по умолчанию получает `?model=gpt-6-astra` **и** multipart-поле `model=gpt-6-astra`. Это проверяемая гипотеза о формате стороннего router, а не подтверждённый его контракт; стандартный Files API не требует модель в URL.
- Поля multipart в логе показываются только как `model=...`, `purpose=...` и `file=[binary N bytes]`; API-ключ, бинарное содержимое файла и промпт не печатаются. Тест проверяет не только JS FormData, но и реальные сериализованные байты multipart-запроса.
- HTTP 400 остаётся окончательной ошибкой конкретной загрузки: один неуспешный запрос не вызывает 8 повторов, смену credential или Responses-инференс.
- Переключатели совместимости: `OPENAI_INPUT_FILE_UPLOAD_MODEL_QUERY=0` отключает только модель в URL, сохраняя multipart; `OPENAI_INPUT_FILE_UPLOAD_INCLUDE_MODEL=0` отключает только модель в multipart. Для стандартного `/files`, отвергающего добавочные поля, отключить оба. В текущем режиме по умолчанию оба включены.

## Если снова 400

Не перебирать автоматически варианты query/headers/`model_name`. Нужны документированный контракт и точный путь `/files` данного router или безопасный запрос его поддержке: где передавать имя модели, принимает ли он ZIP через Files API, разрешает ли `input_file.file_id` в Responses. Нельзя обещать, что query-параметр решит проблему до реального теста.

## Что установить

В этом ZIP находится обновлённый исходный снимок проекта; применяйте с **сохранением остальных файлов вашего существующего репозитория**. В присланной исходной архивной линии V188.110–V188.114 нет `src/index.js` и некоторых упомянутых в package.json скриптов, поэтому такой ZIP нельзя выдавать за самостоятельную новую установку приложения «с нуля». Не удаляйте из своей работающей папки файлы, которых нет в архиве. Не копируйте рабочие `data/`, секреты и базы поверх существующих.

После установки проверьте `[BOT BUILD] V188.115`, отправьте прежний VK ZIP один раз; ожидайте подтверждение `input-file-uploaded`, затем `astra-running/responseId`. При очередном 400 не выполняйте дальнейшие повторные платные попытки вслепую, сначала уточните API router.

## Локальные проверки

Тесты выполняются с mock fetch и не обращаются к реальному router, не подтверждают получение им файла и не могут доказать отсутствие тарификации на его стороне.
