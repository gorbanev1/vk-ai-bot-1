V142 SECOND API-KEY SWEEP + CLEANUP
===================================

Owner command
-------------
Гигорейв тест всех моделей

Что изменилось
--------------
После обычного полного AI-аудита, transport-retry и точечного retry бот теперь делает отдельный контрольный обход API-ключей.

В этот контрольный обход попадает каждый чужой AI-ключ, у которого после основного аудита осталось 0 подтверждённых runtime-моделей. Для такого ключа бот:
1. повторно получает live-каталог/проверяет авторизацию;
2. собирает весь известный набор text/chat-моделей из обоих каталогов и первого прохода;
3. повторно тестирует каждую text/chat-модель в non-stream и stream через provider-aware endpoint chain;
4. повторно тестирует все известные image-generation модели normal + stream, включая NVIDIA Visual каталог;
5. не прекращает проход после первой удачной модели — проверяется весь собранный набор;
6. сохраняет отдельный отчёт key_second_full_sweep.json.

Очистка .env
------------
После контрольного обхода удаляются не только ключи с явным invalid-secret, но и ключи, которые:
- имеют 0 рабочих text/image runtime-моделей после обоих проходов;
- повторно проверены по всему известному model set;
- получили реальные ответы provider на model probes (например 403/404/429/4xx), но ни одна модель не заработала.

Ключ НЕ удаляется, если в контрольном обходе остались только network/timeout/5xx без надёжного provider-level ответа. Это защищает .env от массовой чистки при временном падении провайдера/сети.

Перед любым изменением .env создаётся:
.env.before-ai-key-cleanup-<timestamp>.bak

OPENAI_COMPAT_API_KEY и имена из AI_AUDIT_EXCLUDE_ENV_NAMES по-прежнему защищены от аудита/очистки. GigaChat этой командой не тестируется.

Runtime registry
----------------
Если ключ ожил только в контрольном полном обходе, найденные рабочие key+model+capability всё равно попадают в ai_runtime_modes. Таким образом второй проход не только решает, что удалить, но и умеет вернуть временно неработавший ключ в runtime.

Отчёты
------
AI_FULL_AUDIT_RESULTS/<timestamp>/
- report.txt
- report.json
- results.jsonl
- retry_candidates.json
- key_second_full_sweep.json
- env_cleanup.json (если была очистка)
- AUDIT_STATUS.json
- AUDIT_DONE.json

Проверки
--------
Добавлены regression tests V142:
- полный второй key sweep действительно проходит ВСЕ модели ключа, даже если одна из них уже восстановилась;
- восстановленная во втором проходе модель попадает в runtime registry;
- confirmed-dead key удаляется из .env;
- uncertain network-only key и protected owner key сохраняются.
