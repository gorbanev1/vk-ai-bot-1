# GIGORAVE V188.124 — Astra TXT stream retry и сохранение VK/event правок

Это ПАТЧ поверх работающей папки бота, а не автономный проект для пустой директории: в пакетах этой ветки может отсутствовать src/index.js и часть script-файлов. Не удаляйте отсутствующие в ZIP файлы своей установки.

Остановите процесс, сохраните резервную копию рабочей папки, .env, баз SQLite и data/audit-jobs. Наложите содержимое ZIP поверх текущей рабочей папки. Не стирайте старые job directories. Запустите npm start и проверьте [BOT BUILD] V188.124. Сначала проверьте TXT небольшим фикстурным файлом.

Изменена ТОЛЬКО ветка Astra TXT/MD (и метка сборки). ZIP-аудит по-прежнему использует существующие текстовые batches и собственную durable-политику; VK recovery 3500 сообщений не менялась. Все правки VK/event из V188.123 сохранены.

TXT/MD: сначала один полный текстовый Responses stream; если роутер ЯВНО отвергает размер/контекст (400/413/422), переход к последовательным частям. После stream_read_error: не переключается на non-stream и не меняется ключ. Для одного логического этапа — максимум 3 последовательных POST с ОДНИМ Idempotency-Key и задержками 8/25 секунд. Для каждого этапа пишется data/astra-text-jobs/<jobId>/<stage>/state.json; дельты — в attempt-N.partial.txt; завершённый ответ — answer.txt. Уже полученный responseId запрещает новый POST. Файл partial — НЕ итоговый ответ. Старые задания не возобновляются автоматически после перезапуска: состояние unknown оставлено для расследования.

ВНИМАНИЕ: реальная поддержка Idempotency-Key у стороннего роутера НЕ ДОКАЗАНА. При обрыве потока без responseId повторение того же POST даже с тем же ключом может создать новую ПЛАТНУЮ генерацию. Именно запрошенные пользователем два дополнительных повторения в этом сценарии теперь разрешены по умолчанию; чтобы выключить их, в коде вызывающего обработчика передайте retryOptions: { allowAmbiguousRepost: false } (для отдельной администраторской конфигурации требуется дальнейшая правка). Не представлять одинаковый ключ как доказательство защиты от двойной оплаты.

Технические ограничения: при известном responseId сохранён checkpoint, но GET/poll конкретного TXT-ответа этим изменением не добавлен (контракт роутера неизвестен). Нет подтверждённого real-router end-to-end и автоматического resume целого текстового задания после перезапуска. Базовый ZIP-аудит и Telegram outbox не переписаны. В логах других запросов VK/summary 524 возможны отдельно; к этому patch они не относятся.
